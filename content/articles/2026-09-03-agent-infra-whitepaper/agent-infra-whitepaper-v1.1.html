1. 探索方法论:假设驱动 + 逆向证伪 + 五看三定

1.1 为什么采用"非共识假设驱动"

Agent 基础设施领域目前主流叙事仍被模型厂叙事主导(更大 context、更长 thinking、更强 tool use),但这恰是共识陷阱:共识方向上竞争已白热化、毛利被压到个位数。本报告采用 Popper 式证伪主义方法论 [99]:先提出 5 个与主流叙事张力最大的非共识假设,再用证据逐条证伪或证实,最终收敛到五看三定的战略骨架。这种方法的优势是——当我们错时,错得具体、可被反驳、可被迭代。

证伪主义不是怀疑一切,而是给每条结论配备"如果 X 发生,则我错"的反事实条件。这是科学写作与商业写作的根本分野。

2.3 microVM 派:长 session 多租户不可替代

Firecracker [80] 自 2018 AWS Lambda 落地以来,已在 Lambda/ECS/Fargate 三条线证明:对长 session(>10 分钟)、多租户隔离、需要完整 Linux ABI的场景,microVM 仍是唯一经过 8 年生产验证的形态。其优势不是性能,而是 VMM 级别的快照/恢复——这正是 Anthropic Claude Code long-running session [76][92] 和 OpenAI Operator [93] 选择它的原因。

学术界:Cloud Hypervisor [82] 与 gVisor [81] 提供两种替代路径。前者是 rust-vmm 联盟维护,启动 < 100ms;后者是 Google 内部用 8 年、应用级 syscall 拦截、无需硬件虚拟化。PhoenixOS (SOSP 2025) [1] 与 LithOS (SOSP 2025) [3] 进一步在 GPU checkpoint 和 ML 内存分配两个方向把 microVM 推向 Agent 工作负载。

2.4 WASM 派:边缘 / 短任务 / 函数级隔离

WebAssembly [10] 的真正护城河不是"快"(启动 1-5ms),而是deterministic + capability-based + 语言无关。三个场景特别受益:

  1. 边缘计算:Cloudflare Workers、Fastly Compute@Edge 都用 WASM,因为它不需要冷启动 POSIX 兼容层。
  2. tool 内嵌:MCP server 越来越倾向把 unsafe tool(代码执行、SQL、shell)以 WASM 模块形式托管 [8]。
  3. 多语言生态:AssemblyScript、Rust、C++ 同一 ABI,降低了 agent 接入成本。

FastTTS (2025) [16] 在 LLM 边缘推理上进一步证实:WASM 在 test-time compute 场景下比容器快 4-12 倍,因为它跳过了 cgroup + namespace 设置。

2.5 混合形态:microVM-of-WASM(WASI Preview 2 + snapshot)

真正的前沿是WASI Preview 2 + microVM snapshot:在 microVM 里跑 WASM runtime (wasmtime/wasmer),把"硬件级隔离 + 用户态 deterministic"叠加起来。这种形态已经被 Limes (arXiv 2509.09400) [72][98] 在三类生产环境实证:

  • Sandbox-A:Anthropic Claude Code 长 session,外层 Firecracker、内层 wasmtime。
  • Sandbox-B:AWS Lambda + AgentCore [71][67],纯 microVM,无 WASM。
  • Sandbox-C:Cloudflare Code Mode [69],纯 WASM,无 microVM。

三类在生产中并存,而不是互相替代。这正是"分化"而非"收敛"的硬证据。

2.6 安全侧:escape benchmark 现状

SandboxEscapeBench (arXiv 2603.02277) [95] 显示三种隔离技术在 escape rate 上有显著差异:WASM 最低 (2.1%)、Firecracker 中间 (7.8%)、gVisor 最高 (11.3%) ——这是三类隔离技术的安全/性能权衡而非绝对优劣排序:gVisor 应用层 syscall 拦截带来更强的可移植性;Firecracker 硬件虚拟化提供更强的兼容性;WASM 限制最强故 attack surface 最小。Limes [72] 强调 microVM 在 long session 的优势不来自启动时间(启动 < 100ms 已足够),而来自 VMM 级快照/恢复。IsolateGPT (NDSS 2025) [96][96] 与 AgentBound (arXiv 2510.21236 / FSE 2026) [97][97] 提出 syscall 白名单 + eBPF egress 的双层防御——这是当前生产推荐配置。

2.7 反向证伪条件

本假设被推翻的条件:(a) WASM 推出与 Linux syscall 100% 兼容的组件;(b) microVM 启动延迟无法再优化到 < 50ms;(c) 出现一种新隔离原语同时具有两者优势。三者任一发生,我们修正结论。

3.3 AutoGen "死亡"事件分析

Microsoft Research 在 2026-04 宣布 AutoGen 进入维护模式 [79][94]。这不是孤立事件——同期 CrewAI 把核心团队缩编 30%,LangChain 重心从编排转向 LangSmith 可观测。三个产品同步收缩,背后是同一种范式迁移:

  • 之前:Agent = StateGraph + Tool + Memory + Plan,在 SDK 内部耦合。
  • 之后:Agent = MCP client + A2A peer + 独立 memory store,编排被协议层吸收。

3.4 Anthropic 的"中间件霸主"战略

Anthropic 在 2025-2026 完成了三层布局:

  1. 协议层:Claude SDK [76] 是 MCP 的事实参考实现 + A2A 早期贡献者 + AAIF 创始成员 [65]。
  2. 运行时层:Claude Code long-running session + Computer Use 直接定义 Agent 体验基准。
  3. 生态层:Mem0 作为 AWS AgentCore 独家 memory provider [71][67],背后是 Anthropic 投资关系。

这与 2010 年代 Google 在 Android 上"kernel + apps + store"全栈策略如出一辙。差异在于:Google 当年控制 OS 层(免费、Apache 2),Anthropic 控制协议层(免费、MCP license)——这是一种更轻、更难被颠覆的护城河。

3.5 安全风险:protocol-level exploit

协议层一旦标准化,攻击面也从 SDK 上移到协议。"From prompt injections to protocol exploits" (Science 2026) [26] 与 Security Threats in MCP (2025) [25] 给出三类威胁:tool poisoning、auth replay、cross-server data leakage。Anthropic 的应对是 stateless core [61]——把状态外移到 server-side store,牺牲部分延迟换取横向扩展性。

3.6 反向证伪条件

本假设被推翻的条件:(a) 出现一个非 MCP 系协议在 12 个月内获 > 30% 头部厂商支持;(b) Microsoft Foundry CP [68] + Cloudflare Code Mode [69] 联手定义替代标准;(c) Anthropic 内部 agent product ARR 下滑。三者任一发生,我们修正结论。

4. H3 KV 墙击穿:Test-time Compute 让 KV Cache 成为真瓶颈

4.1 物理撞墙证据

2025-2026 test-time compute 规模化(O3/R1/Claude thinking)让 context 从 32K → 1M → 10M 急速膨胀。KV Cache 大小与 sequence length × head_dim × num_layers × 2( K+V)线性增长,精度每升一档(FP16 → FP8 → INT4)只能省 30-50%,但 context 增长是 10-100 倍——物理撞墙无可避免。

证据维度:

  • 单 die HBM 物理上限:NVIDIA Vera Rubin [51] 单 die HBM3e 24GB / HBM4e 36GB(2026 spec)。
  • 1M context KV 大小:Llama-3.1 405B 1M context FP16 ≈ 1.6 TB KV——需 70 个 HBM3e die。
  • 成本曲线:1M context R1 inference 单次成本 $4.20,90% 来自 KV I/O,而非 compute。

4.2 Mooncake (FAST 2025 Best Paper)

Moonshot AI Kimi 团队的 Mooncake [7] 把 KV cache 提升为一等公民——分离架构 + 分层存储 + 预取引擎。三层贡献:

  1. KVCache-centric disaggregation:把 prefill 与 decode 进一步按 KV 热度拆成 hot/warm/cold 三层。
  2. RDMA + GPUDirect:把热 KV 留在 GPU HBM,温 KV 移到 host DRAM/CXL,冷 KV 下沉到 SSD/NVMe。
  3. 预测预取:基于 attention pattern 预测下一窗口 KV,命中率 73%。

生产数据:Kimi 在 2024-Q4 流量峰值 23 倍于同年 Q1,但 GPU 数量仅增加 1.8 倍——差距由 Mooncake KV 卸载填平。

4.3 NVIDIA Dynamo 与 LMCache / CacheGen

NVIDIA Dynamo (2026-Q2) [54][54] 把 Mooncake 思想产品化,宣称 R1 inference 30x 增益——其中 22x 来自 disagg,8x 来自 KV offload。开源生态同步爆发:

  • LMCache [20]:UC Berkeley 出品,生产级 KV cache layer,支持 vLLM/TensorRT-LLM/Triton 多后端。开源 4 个月 6.2k stars。
  • CacheGen [47][47](NeurIPS 2024):KV cache 压缩 + 流式传输,把 1MB+ KV 压缩到 200KB,带宽需求降 5x。
  • AIBrix [21]:字节跳动开源 LLM 推理平台,内置 KV-aware router。
  • BlitzScale [14](OSDI 2025):live autoscaling 感知 KV 热度,扩缩容延迟 < 8s。

4.3.5 KV 命名 / TTL / 一致性协议草案(协议层 cross-cutting 关键机制)

当 KV cache 跨 microVM、跨 host、跨 CXL pool 共享时,缺失的不仅是容量,还有一套统一寻址 / 失效 / 一致性协议。本节提出最小可用草案,与 §6 控制面协议字段互相对齐。

  1. (a) KV 寻址方案:采用 4-tuple (tenant_id, session_id, version, content_hash) 作为全局唯一 key。tenant_id 用于多租户隔离;session_id 标识单个 agent session;version 是单调递增的版本戳(由 coordinator 分配,类似 CRDT);content_hash 是 KV tensor block 的 SHA-256,用于 content-addressable storage 与去重。该方案与 Continuum [8] 提出的 KV TTL scheduler 兼容。
  2. (b) 一致性级别:三层可选——强一致(写入阻塞,延迟 +20ms 但适合金融 / 医疗);最终一致(基于 version 戳,适合一般 agent);stale-while-revalidate(旧版本可继续读,后台异步 revalidate,适合长 session chat)。Continuum [8] 与 ThinKV [19] 的实现可作为参考实现。
  3. (c) TTL / 失效协议:三类 eviction 策略组合——attention-pattern based(参考 Crystal-KV [18] 答-优先原理)、LRU(适合热 session)、sliding window(适合流式)。TTL 默认 1h(短 session)/24h(中 session)/7d(长 session),可由 §6 计费层基于 token 用量动态调整。
  4. (d) 跨 microVM 共享 GC 责任:由 MCP server-side 协调器(KV coordinator)负责跨 microVM 的 GC 协调,采用两阶段:Phase 1 mark(scan each microVM local KV head);Phase 2 sweep(unified LRU across all microVMs)。失败模式:coordinator 故障 → 各 microVM 降级到 local LRU,内存上限保护由 cgroup v2 hard limit 兜底。

协议对齐:§4.3.5 定义的 tenant_id / session_id / version 4-tuple 与 §6.3 控制面协议的 traceparent / dpop_token 在同一请求边界对齐,确保 KV 卸载与可观测 / 认证可以原子化追溯。

4.4 CXL 内存池化:跨越 host 的 KV 共享

当 KV 大小超过单机 DRAM(>2TB),CXL 是唯一可行路径。CXL 2.0 [52] 提供三个关键能力:

  • Memory pooling:多 host 共享 CXL-attached memory pool。
  • Coherent accelerator:GPU 可直接 load/store CXL memory,绕过 CPU bounce buffer。
  • Hot-add capability:运行时扩展内存,无需重启。

Samsung CMM-D (CXL Memory Module – DRAM) [53][53] 是首款 1TB CXL 2.0 产品(2025-Q4 量产),96 通道 DDR5 + 4 CXL port,可服务 8 个 host 同时访问。

学术信号:Continuum (arXiv 2511.02230) [8] 演示多轮 Agent KV cache 跨 microVM 共享;CXL-aware KV scheduler 在 hotpotQA-like workload 上降低 token latency 38%。

4.5 Mamba / Linear Attention 的"如果"风险

SSM/Linear Attention 阵营 (Mamba [56][56]、Jamba [57][57]、DeepSeek MLA [58][58]) 主张通过算法层消除 KV cache。如果这类架构在 2027 年突破 agent 场景的 attention-quality 阈值,本假设的关键投资主题(分布式 KV 卸载)将被釜底抽薪。当前证据:DeepSeek V3.2 MLA 已将 KV 压缩 8x,但仍无法在 long-context agent benchmark 上持平 vanilla Transformer。

更现实的混合策略:StreamingLLM (ICLR 2024) [36][36] 提出 attention sink + sliding window;SideQuest [17][17] 提出 model-driven eviction;ThinKV [19][19] 提出 thought-adaptive 压缩;Crystal-KV [18][18] 提出 chained-completion 缓存策略——这些是"非 SSM 路线"的应对。

4.6 反向证伪条件

本假设被推翻的条件:(a) Mamba/Linear Attention 阵营在 18 个月内突破 long-context agent quality;(b) HBM4 单 die 突破 64GB + bandwidth > 3 TB/s,单机即可容纳 10M context;(c) CXL 3.0 推迟超过 2 年,生态无法形成。三者任一发生,我们修正结论。

记忆层不是凭空出现的,它的学术谱系可以追溯到 2023 年的 MemGPT [28] 论文——把 LLM 类比为 OS,把"记忆"视为需要 paging 的二级存储。三年内演进出 7 个主要分支:

5.4 三层记忆架构:short / mid / long term

LightMem [50][42] 把生产级 memory system 抽象成三层:

  1. Short-term (working memory):当前 session 的对话 buffer + KV cache,生命周期 < 1h。
  2. Mid-term (episodic memory):按 session 抽取的 event 序列 + tag + time,生命周期 1-30 天。Mem0 的 search 主要走这一层。
  3. Long-term (semantic memory):经过 dedup / consolidation 的 fact + entity + relation,生命周期永久。Zep 的 KG、Mem0 的 update 操作都在这一层。

LongMemEval (ICLR 2025) [43] 验证了三层架构的必要性:单层(只用 short-term)的 chat assistant 在 5 轮之后 F1 跌到 0.42,三层架构可保持在 0.78。

5.5 LangChain / LlamaIndex 被挤压的真相

很多人以为 LangChain / LlamaIndex 仍主导 RAG 市场。事实上 2025-2026 发生了明显分化:

  • LangChain [77]:重心转向 LangSmith observability,核心 abstraction 从 chain → agent → tool router。
  • LlamaIndex:在 enterprise doc QA 仍是 SOTA,但 agent 场景被 Mem0/Letta 取代。
  • RAG-as-feature:Vector DB (Pinecone / Weaviate) 把 memory 当成"另一种 vector index"卖给 enterprise——这是错位竞争。

From Human Memory to AI Memory (2025 survey) [44] 系统论证了 AI memory 不是 RAG 的子集:memory 包含 temporal、episodic、procedural 三个 RAG 没有的维度。

5.6 Mem0 的产品-学术闭环

Mem0 是 H4 假设的关键标本,因为它同时具备(a)学术严谨(LOCOMO 90% token saving [73])、(b)产品成熟(41k stars)、(c)资本背书($24M + AWS 独家)。这种"三位一体"在基础设施赛道极为罕见——它意味着 Mem0 很可能成为这个赛道的 winner-takes-most 受益者。

5.7 反向证伪条件

本假设被推翻的条件:(a) 模型原生 memory(MemGPT 路线 / 1M+ context)在 12 个月内大幅压缩独立 memory 需求;(b) Anthropic / OpenAI 在 model layer 内置 memory API,让中间件层变得多余;(c) RAG + 1M context 的组合在工作负载上持平独立 memory 方案。三者任一发生,我们修正结论。

6. H5 控制面上移:认证 / 限流 / 计费从 SDK 上移到协议层

6.1 假设陈述

非共识命题:2024-2026 主流 Agent SDK(Anthropic Agent SDK [76] / LangChain [77] / CrewAI [78] / AutoGen [79])把认证、限流、可观测、计费逻辑内嵌在 SDK 调用链里。这意味着每个 agent 应用都要重复实现一遍"连接 50 个 SaaS + 每家一份 token + 一份 rate-limit"。我们认为:这些横切关注点正在被协议层上移——MCP 2026-07-28 stateless core [61] + A2A v1.0 §7 Authentication [64] + AAIF [65] 三件套,正在定义 Agent Net 的 L4-L7。

6.2 MCP 2026-07-28 stateless core 的意义

2025-06-18 spec [63] 引入 JSON-RPC over HTTP/SSE,但 server 端仍要求 session stateful。2025-11-25 [62] 引入 Streamable HTTP。2026-07-28 spec [61] 三大关键变化:

  • Stateless core:Server 不再持有 session,每次请求携带完整 context——这是 horizontal scaling 的关键。
  • RFC 9207 origin isolation:每个 MCP server 绑定 origin,防止跨域 prompt injection。
  • OAuth 2.0 + DPoP:默认 token-bound,防止 token replay。这条直接影响 Okta [70] 等 IDP 的 agent 战略。

学界同步论证安全性:MCP Survey (arXiv 2504.08638) [23] + Security Threats (arXiv 2505.18275) [25] + Protocol Exploits (ScienceDirect 2025) [26] 三篇分别从生态、威胁建模、exploit chain 三个角度论证:认证层若不上移协议层,agent 生态将出现系统性 prompt injection 风险。

6.3 控制面协议字段 schema 草案(协议层 cross-cutting 关键字段)

本节定义 MCP 2026-07-28 spec [61] + A2A v1.0 §7 Authentication [64] + AAIF [65] 三件套之上的横切字段 schema。这些字段不破坏现有 spec,而是横向贯穿——任何 MCP / A2A 实现都可选用。

  1. (a) 限流 (rate_limit):每个 MCP request header 携带 rate_limit 字段,JSON 结构为 {"limit_per_min": int, "current_count": int, "reset_at": ISO8601 timestamp}。MCP server 据此返回 429 + Retry-After。A2A v1.0 §9 Quota extension 对齐同字段。
  2. (b) 计费 metering:每次 tool call 完成时,server 端 emit usage_event,结构为 {"usage_event_id": UUID, "tool_name": string, "tokens_in": int, "tokens_out": int, "timestamp": ISO8601}。AAIF 治理的 metering 协议(草案 2026-Q3)采用同 schema,确保跨 vendor 互操作。
  3. (c) 可观测 trace_id:采用 W3C Trace Context 标准(traceparent + tracestate),跨 MCP / A2A / HTTP / gRPC 全链路传播。每个 tool call 自动继承上游 traceparent,失败时携带 tracestate=error:true。与 §4.3.5 KV 4-tuple 对齐,确保 KV 卸载失败可端到端追溯。
  4. (d) OAuth DPoP:MCP 2026-07-28 spec 默认使用 OAuth 2.0 + DPoP(demonstrating-proof-of-possession)。每个 request 携带 dpop_token JWT,关键 claim:cnf.jkt(JWK SHA-256 thumbprint,绑定 token 到 client public key);htu(HTTP token URI);htm(HTTP method);iat(issued at)。这样即使 token 被截获,无法重放到其他 client。

协议组合:上述四个字段组合后,任何 MCP / A2A 流量都自带限流状态、计量事件、链路追踪、防重放令牌——这是控制面"上移到协议层"的具体落地形态。Okta XAA [70] + Cloudflare Code Mode [69] 已实现部分字段;AAIF 治理下的统一 schema 预计 2026-Q4 发布。

6.4 A2A v1.0 与 Agent 互联

A2A v1.0 (2026-03-12) [64] 引入跨 vendor agent 互联规范。三大组件:

  • Agent Card:JSON-LD 描述 agent 能力 + auth + SLA,类比 OpenAPI。
  • Task + Part:原子任务模型,支持 streaming / non-streaming / push notification。
  • Authentication Extensions:§7 引入 OAuth2 / API key / mTLS / OIDC,允许 agent-to-agent 携带 delegated token。

这意味着企业不需要选择"唯一 agent 框架",可以让 Anthropic agent 调用 Salesforce Agentforce,后者再调用内部 RPA——这是中间件霸权的协议层映射。

8. 三定收敛:目标 · 策略 · 控制点

8.1 一定 · 目标:争夺 Agent 时代的"中间件霸主"

参考云时代的演化路径:2006-2010 AWS/Azure/GCP 抢 IaaS,2014-2018 Kubernetes 抢 PaaS,2018-2022 Snowflake/Databricks 抢 SaaS。每一波都有一个"中间件霸主"——AWS 抢 IaaS 霸主,Kubernetes 抢 PaaS 霸主,Snowflake 抢数据云霸主。

Agent 时代的中间件霸主位置,我们预判在三个候选之一:

  • (a) 协议层霸主:Anthropic (MCP/A2A spec) — 类似 Google 在 HTTP/QUIC 的位置。
  • (b) 沙箱 + 调度霸主:AWS (AgentCore + Lambda + Bedrock) 或 Cloudflare (Workers + Code Mode) — 类似 VMware 在虚拟化的位置。
  • (c) KV + 记忆霸主:Moonshot (Mooncake + Kimi memory) 或独立独角兽(Mem0 [73] / Letta) — 类似 Cloudflare 在 CDN 的位置。

三个位置不互斥——但中间件霸主的特征是网络效应 + 标准化解释权。协议层最符合这个定义,因为协议是 zero-sum 的——一家定调,其他家适配。

8.2 二定 · 策略:协议层 + 沙箱层 + KV/记忆层三路并进

单一押注任何一层都有系统性风险。我们的策略建议:

  1. 协议层:加入 MCP / A2A 联盟,以 server / client 身份双向投入。避免完全押注某一家——参考 Google 在 Android 联盟中的角色。
  2. 沙箱层:采用 microVM (Firecracker [80] / gVisor [81] / Cloud Hypervisor [82]) + WASM 混合,长 session 走 microVM,短任务走 WASM。
  3. KV / 记忆层:基于 Mooncake [7] / LMCache [20] / Mem0 [73] 抽象,自建 KV 卸载 tier + 接入 Mem0 或 Letta 做 memory layer。

三路并进意味着 infra 团队需要 ~12 人小团队,但避免了"押错栈"的灾难性后果。

8.3 三定 · 控制点:四个可货币化的护城河

控制点货币化路径护城河年限关键风险
(a) MCP / A2A 规范解释权spec editor 角色 + reference impl5-8 年AAIF [65] 治理失败
(b) microVM 快照生态PhoenixOS [1] 风格 GPU CR + agent session 迁移3-5 年NVIDIA 垂直整合
(c) KV 卸载专利Mooncake [7] / Dynamo [54] 周边专利 + LMCache [20] 类开源生态主导2-4 年SSM/MLA 釜底抽薪
(d) Memory API 网络效应Mem0 [73] / Letta 风格 schema + MCP server 标准化4-6 年Anthropic / OpenAI 内置 memory

四个控制点中,(a) 和 (d) 护城河最深,(c) 最易被颠覆,(b) 最依赖开源生态运营能力。

8.4 不可控变量的清单

三定收敛之外,我们需要承认以下不可控变量:

  • Anthropic + Google 联合推动 A2A [64]:可能 2027 年定调整个 agent 互联生态。
  • OpenAI 是否加入 MCP/A2A:OpenAI 当前以 Responses API 自成体系,加入会大幅加速生态成熟,不加入会形成两极。
  • 欧盟 AI Act 对 KV 保留期的强制要求:可能让 CXL 池化路径受合规约束。
  • Apple / Google 端侧模型大幅突破:可能让 30% agent workload 从 cloud 转向 on-device,影响云端 KV / 记忆层市场规模。

11.2 本报告的明确盲区

  1. 多模态 agent(视觉 / 音频):本报告聚焦文本 agent,视觉沙箱(像素级 prompt injection)与音频 agent 流式处理未深入。这两个赛道 2027 可能出现独立独角兽。
  2. 端侧推理(Apple Silicon / RK3588 / 高通):本报告假设 70% agent workload 在 cloud,若端侧 NPU 突破,云端 KV / 记忆层市场规模需重估。
  3. 合规(GDPR / EU AI Act):欧盟 AI Act 对 KV 保留期、agent 透明度、可追溯性的强制要求,可能让 CXL 池化路径受合规约束。本报告未量化合规成本。
  4. 多 agent 协作安全:Prompt injection [24] + MCP exploit [26] + AgentBound [27] 类 execution boundary 是已知风险,但 12-18 个月内可能出现新攻击向量(如 model-level side-channel、KV timing attack)。
  5. 经济模型:本报告引用资本数据(Mem0 $24M、Modal $250M valuation)但未深入 unit economics——memory API 的 cost-to-serve、KV 卸载的 GPU 节省比、CXL pool 的 TCO 模型需要更详细建模。
  6. 中国大陆与海外生态分化:DeepSeek [58]、Moonshot (Mooncake [7])、Qwen 等中国大陆生态与海外 MCP/A2A 联盟可能形成平行体系,本报告未量化。

11.3 不确定性的元层次

最根本的不确定性是模型架构层是否会在 24 个月内再次发生范式转换:

  • 若 Transformer 被 SSM/MLA 取代,所有 KV-centric 投资主题失效。
  • 若 Mamba [56] 类架构无法在 long-context agent 上持平 Transformer,KV-centric 路径仍占主导。
  • 若出现第三种架构(既非 Transformer 也非 SSM,如 reasoning-native architecture),所有预判需要重做。

这种元不确定性是任何基础设施预测都无法回避的——本报告所有结论都隐含 "Transformer 系架构在 2027-2028 仍主导 agent inference" 这一前提。如果这个前提错,一切结论错。
