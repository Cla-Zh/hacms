  • 主方案 1 · CXL (跨设备内存池) — 2024-12 发布 CXL 3.2 + 2025-11 发布 CXL 4.0 (128 GT/s, 256 GB/s 单向/512 GB/s 双向). 用于 KV Cache 跨节点池化.
  • 主方案 2 · NVIDIA CMX (Context Memory Storage Platform) — NVIDIA 2026-03 GTC 2026 发布, 由 BlueField-4 DPU (126 亿晶体管, 64 核 Grace, 800 Gb/s) + Spectrum-X (409.6 Tb/s SN6800) + Rubin 平台 组成. 专门为 KV Cache 设计的 G3.5 pod-level context memory, 5× TPS 提升, 5× 能效.
  • 主方案 3 · 灵衢 UnifiedBus — 这是 华为 2025-09-18 发布的超节点互联协议, 2.1 μs 延迟, 200 m 光互联, TB 级带宽, 支撑 Atlas 950/960 SuperPoD 8,192-15,488 昇腾卡.
  • 主方案 4 · Google TPU ICI — TPU v4/v5p/v6e/Trillium/TPU7x Ironwood 系列, 2D/3D torus + OCS, v6e 每 chip 双向 800 GBps aggregate, TPU7x Ironwood 9,216 chip pod 9.6 Tb/s aggregate.
  • 扩展方案 4 个: NVLink-C2C + NVLink 6 (Vera Rubin NVL72 3.6 EFLOPS, 260 TB/s), UALink 1.0 (2025-04, 200 Gbps/lane, 1024 acc/pod), AMD Infinity Fabric + Ultra Ethernet 1.0 (2025-06, 800G/1.6T), PCIe 6.0/7.0 + Cisco Silicon One G200 (51.2 Tbps).
  • CXL 内存池化硬件 (支撑层): Samsung CMM-D MD220 (256GB) / MD310 (CXL 3.2 72 GB/s), Meta Vistara ASIC (ISCA 2026 158 核 Turin + 768 GB DDR5), Astera Labs Leo (Azure M-series 64 TB), MemVerge + XConn 100 TiB 商业池.
  • KV Cache 视角: NVIDIA CMX 是 唯一 集成 GPU HBM + Spectrum-X + BlueField-4 的 KV Cache 方案, 5× TPS 提升. CXL 内存池化 256 ns 延迟是软件层, 200-500 μs CMX 延迟是 G3.5 层. TPU 用 prefix cache + ICI 共享. 灵衢 2.1 μs 适合推理跨机柜 KV Cache 拉取.
  • AI 训练视角: NVLink 6 3.6 TB/s (Vera Rubin) 是 训练场景的金标准 (NVL72 260 TB/s per rack, 100 kW). TPU ICI 50 GB/s/link × 6 links ≈ 300 GB/s per chip, 4D torus 适合张量并行的 all-reduce. 灵衢支撑 8,192 张昇腾卡 HPL/AI 训练.
  • AI 推理视角: KV Cache 占用随 context 长度爆炸, 70B 模型 prompt 128K 时每卡需 80 GB+ 仅 KV Cache. NVIDIA CMX + CXL 内存池化是 关键, 而不是堆更多 HBM. 推理服务 total cost = 计算 + 内存 + 互联, 互联正成为新瓶颈.

📖 §1 背景: Memory Wall 4.0 — 为什么 KV Cache 需要新互联

在 LLM 推理中, KV Cache 占用随 context 长度线性增长. 一个 70B 模型 (Llama-3 70B) 在 FP16 精度, 128K context, batch=8 时, 每张卡需要约 80 GB 仅 KV Cache (远多于模型权重 140 GB 的一半). 当 8 卡 NVLink 互联时, 8x H100 80GB = 640 GB 总内存, 可装下 8 组 128K context; 但 跨节点 (没有 NVLink 桥接) 时, 每节点 80 GB 必须装下整组 KV Cache, 否则只能跨节点 KV Cache 搬运.

2026 年 LLM 推理场景越来越面临 4 个 Memory Wall 难题:

  • Memory Wall 1.0 — HBM 容量 vs 计算. 1 张 H100 80 GB, 跑 1 个 200B 模型推理需要 2-3 张卡.
  • Memory Wall 2.0 — HBM 带宽 vs 算力. HBM3e 4.8 TB/s, B200 5x PFLOPS, 算力带宽比 1:2000.
  • Memory Wall 3.0 — KV Cache 共享. 1 个 prompt 1000 个用户请求, 99% 共享 prefix, 但每请求独立存储 KV Cache, 浪费 99% 显存.
  • Memory Wall 4.0 (新增) — 跨节点 KV Cache 共享. 单节点 8 卡 HBM 已不够, 跨节点 KV Cache 共享需要新协议.
💡 核心洞察: 解决 KV Cache 共享问题有 3 条路: (a) 软件层 — vLLM/SGLang PagedAttention + RadixAttention; (b) 硬件层 — HBM 容量扩大 (HBM4 12-Hi 36 GB); (c) 互联层 — CXL/NVIDIA CMX/灵衢/UALink 跨设备/跨节点共享. 2026 真正的工程挑战在 (c).
图 1.1 · CXL 3.0 三协议 (cache/mem/io) 示意 — 出自 CXL 联盟官方 3.0 White Paper (2023-12) [ref]

看图: CXL 由 3 个子协议组成 — CXL.io (设备枚举), CXL.cache (加速器缓存主机内存), CXL.mem (内存设备被主机访问). 3.0 以后支持 port-based routing, 4.0 进一步翻倍到 128 GT/s.

🌐 §2 主方案 1 · CXL 3.0/3.1/3.2/4.0 — 内存池化协议

CXL 是 Intel 2019 年主导 创立的 CPU↔设备/内存直连协议, 与 PCIe 6.0/7.0 共用物理层. 到 2026 年 8 月, CXL 联盟已经有 200+ 成员, 包括 Intel, AMD, NVIDIA, Samsung, SK Hynix, Micron, Microsoft, Google, Meta, AWS, ARM, IBM, HPE, Dell, Cisco 等.

2.1 CXL 协议家族 — cache/mem/io 三合一

CXL 1.0 (2019) 定义 3 子协议:

  • CXL.io — 复用 PCIe 5.0 物理层, 设备枚举/DMA/中断.
  • CXL.cache — 设备端 (Type 1/Type 2) 缓存主机内存, 保持 cache coherency.
  • CXL.mem — 主机访问设备端内存 (load/store 语义), 设备 (Type 3) 是被动内存.

CXL 2.0 (2020) 新增: CXL 2.0 内存池化, CXL IDE (Integrity + Data Encryption).

CXL 3.0 (2022-08) 重大升级:

  • 物理层: PCIe 6.0, 64 GT/s PAM4, x16 单向 128 GB/s, 双向 256 GB/s.
  • 新增 CXL 3.0 Fabric, 支持 Fan-In Memory Pooling (多主机共享 1 设备) 和 Fan-Out Memory Pooling (1 主机扩多设备).
  • Port-Based Routing (PBR) — 多 host 通过 CXL switch 互联, 每设备可达 1,023 hosts, 4,096 devices.
  • 对 flit 编码: 68B/256B, 256B flit 是 3.0 优化的核心.

🚀 §3 主方案 2 · NVIDIA CMX (Context Memory Storage) — 上下文记忆存储平台

3.4 Dynamo + NIXL + Grove 软件栈

CMX 不是孤立硬件, 需要 NVIDIA 全栈软件配套:

  • NVIDIA Dynamo — 推理编排框架, 替代 Triton Inference Server. 处理 prefill/decode 分离 + KV block 管理.
  • NIXL (Inference Transfer Library) — 跨 CMX/host memory/GPU HBM/SSD 块迁移, 统一接口.
  • NVIDIA Grove — 拓扑感知调度, 跨 rack 调度 workloads 维持 KV locality.
  • DOCA Memos — CMX + BlueField-4 控制面, 安全 + 加密 + 监控.

3.5 5× TPS 数学 + VAST 实际部署

NVIDIA 官方声称 CMX 提供 5× higher TPS (Tokens Per Second) 和 5× power efficiency vs 传统存储. 数字来源: VAST Forward 2026 大会 (2026-02), 假设 40-60% cache hit rate for enterprise AI flows.

VAST 给出的数学模型:

  • 无 CMX: GPU 等待 65 秒 (从 G4 SSD 重 compute KV Cache)
  • 有 CMX: GPU 等待 3 秒 (从 BlueField-4 CMX 拉 KV Cache)
  • 60-130% 性能提升 (基于 cache hit 假设)
  • 10,000 用户 × 32 GB KV Cache = 320 TB 系统, 支持"instant resume"

VAST 实际部署: VAST CNode 集成 NVIDIA GPU + BlueField-4 DPU + SpectrumX 硅光交换机, 直接接入 VAST 存储集群. 2026-03 GTC 公开.

CMX 部署生态 (2026 H2 GA):

  • DDN, Dell, HPE, Hitachi Vantara, IBM — 主流存储厂商
  • Nutanix, Pure Storage (Everpure), Supermicro, VAST Data, WEKA — 新一代 AI 存储
  • Cloudian, MinIO, NetApp — 待加入
⚠️ 重要概念区分: CMX 跟 CXL 内存池化 (不同层):
  • CXL 内存池化 (~256 ns) — 内存层级 G2 扩展, 容量 TB 级, 适合 hot KV Cache
  • NVIDIA CMX (200-500 μs) — 内存层级 G3.5, 容量 PB 级, 适合 warm KV Cache + 跨 rack 共享
  • 两者 不是替代, 是 互补: 推理时 hot KV 走 HBM/CXL, warm KV 走 CMX, cold KV 走 G4 SSD

🚀 §5 主方案 3 · 灵衢 UnifiedBus — 华为超节点互联协议

🚨 再次强调: "灵衢" 不是阿里方案, 而是 华为 2025-09-18 在 HC2025 大会 正式发布的 UnifiedBus (UB) 协议. 华为徐直军主题演讲 + 杨超斌 SuperPoD 创新演讲配套. 官方产品: Atlas 950 SuperPoD (8,192 张昇腾卡) + Atlas 960 SuperPoD (15,488 张昇腾卡) + Atlas 950/960 SuperCluster.

5.1 灵衢 4 层协议架构 + 6 大设计原则

灵衢采用 4 层协议栈 + 6 大设计原则:

  1. 物理层 — 光 + 电, 200 m 光互联距离
  2. 数据链路层 — 帧编码 + 链路层可靠
  3. 网络层 — 路由 + QoS
  4. 传输层 — 端到端可靠 + 拥塞控制
  1. 总线级互联 — 像访问本地内存一样访问远程内存, 2.1 μs 端到端延迟
  2. 平等协同 — N:1 不分主从
  3. 全量池化 — 内存、显存、HBM 全池化
  4. 协议归一 — 训练、推理、CPU 通信统一协议
  5. 大规模组网 — 8,192-15,488 昇腾卡
  6. 高可用 — 多路径 + 故障自动重路由

5.2 关键性能指标 + KV Cache 意义

☁️ §7 主方案 4 · Google TPU ICI — 2D/3D torus + OCS

Google TPU 是 另 1 个范式 — 把"互联" 做到芯片内部 (ICI - Inter-Chip Interconnect), 而不是 host↔device. 2020 年 TPU v4 引入 3D torus + OCS 光电路开关, 2024-2025 TPU Trillium/Ironwood 持续强化.

看图: TPU v4 pod 的 4×4×4 立方体, 每个节点 (chip) 6 个链路 (X+, X-, Y+, Y-, Z+, Z-) 双向连接, 形成 3D torus. 拓扑右边的 OCS (Optical Circuit Switch) 可以在运行时重新配置链路, 绕过故障节点.

⚠️ 常见数字误区: 网上常说 "TPU v4 每链路 6.4 Tb/s" — 这 错误! 官方论文 (Jouppi et al. 2023) 数据是 50 GB/s 单向 per link, 6 links aggregate 300 GB/s 单向 per chip.

OCS 是 TPU v4 核心创新: 4,096 chip pod 中任意 1 块 chip 故障, OCS 重路由绕过, 训练不中断. ISCA 2023 论文: 4,223 chip pod 实验中 (含 197 块故障), 99.98% 可用性.

⚙️ §9 扩展方案 B · UALink 1.0 — 开放加速器互联

2024-05, 22 家公司发起 UALink (Ultra Accelerator Link) 联盟, 2024-10-29 正式注册. 创始成员: AMD, AWS, Astera Labs, Cisco, Google, HPE, Intel, Meta, Microsoft, Synopsys, 等等. 2025-04-07 发布 UALink 1.0 规范.

9.1 UALink 1.0 关键参数

  • 200 Gbps per lane (类似 PCIe)
  • x16 = 200 GT/s aggregate
  • 每 pod 1,024 accelerator (Hopper NVLink 576 的 1.78×)
  • 替代 NVLink 私有协议的目标
💡 UALink vs NVLink: NVLink 是 NVIDIA 私有 (用于 Hopper/Blackwell/Rubin), UALink 是开放 (用于 AMD MI355X, Intel Gaudi 4, AMD CPU, 等等). 两者 不兼容. UALink 是 OpenCAPI/Gen-Z 失败的延续 — 业界尝试对抗 NVLink 私有生态, 2026 年看 UALink 1.0 + AMD 顺水能否成事.
