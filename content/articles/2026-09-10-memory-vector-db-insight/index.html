H2: HBF 会成为 AI 推理的 HBM 与 SSD 之间新层

  • 结论: HBF 有可能成为 GPU 旁的「第二级缓存」, 改变 AI 推理的存储层级

H3: CXL 内存池化会重塑 Vector DB 经济性

  • Samsung CMM-D 单条 256GB / 128GB / E3.S / PCIe Gen 5 / CXL 2.0
  • MemVerge + XConn + Micron SC25 演示 100 TiB CXL pool, Vector DB 冷层下沉 $/TB -60%
  • 结论: Vector DB 的 hot index 仍放 DRAM, cold-tier embedding 下沉到 CXL memory pool

H4: Agent Memory 成为新独立赛道

内存范式跃迁 (2026 H2)

2026 是 AI 内存"超级周期"的拐点年

2026 年是 AI 驱动的存储芯片 "20 年未遇的大行情" 起点。摩根大通 预测 DRAM 市场将进入 2024–2027 年的 "前所未有的四年定价上行周期"，到 2027 年全球存储市场规模有望逼近 3000 亿美元 [391]。TrendForce 估算 HBM 占 DRAM bit 出货量比例从 2023 年的 2% → 2024 年 5% → 2025 年超过 10%；HBM 在 DRAM 营收占比预计 2024 年超 20%、2025 年超 30% [392]。

服务器存储在整体存储市场的占比已从过去 20% 提升至 40% (长城证券测算, 转引自《星岛》) [393]。TrendForce 进一步预测三大原厂 HBM 晶圆投入占 DRAM 总晶圆投入比例将在 2025 年底、2026 年底、2027 年底分别达到 18%、22%、30%，同期 HBM bit 供给占总 DRAM bit 比例 8%、9%、13% [394]。

SOCAMM2 / LPDDR 服务器化 (AI 推理新层级)

  • HBF (HBM Flash): SK hynix 在 SK hynix Newsroom 公开讨论 HBF 作为 AI 数据存储的下一代 (news.skhynix.com)。

AI 推理对内存的需求变化 (KV cache / 长上下文)

向量库范式跃迁

向量数据库并非一夜之间出现。其技术演进可清晰划分为三个时代:

ANN 算法时代 (2017–2020):从学术论文到工业可用

向量检索的核心是 Approximate Nearest Neighbor (ANN) 算法,即在召回率与性能之间做权衡,而不是逐一精确比对所有向量。

  • HNSW (Hierarchical Navigable Small World) 由 Yury Malkov 和 Dmitry Yashunin 在 2016 年提出 (arXiv:1603.09320, 2016 年首次提交,2018 年正式发表于 IEEE TPAMI) 出处。HNSW 基于多层导航小世界图,可达到对数复杂度,被 hnswlib 库实现后在 GitHub 获 4300+ stars 出处,成为绝大多数主流向量库的默认索引。
  • IVF (Inverted File Index) — 将向量空间切分为若干 Voronoi 单元 (倒排桶),查询时只搜索最近邻的几个桶。Facebook AI 的 Faiss 库 (2017) 将 IVF 与 PQ (Product Quantization) 组合成 IVFPQ,大幅压缩向量内存并加速距离计算 出处 (KScaNN 论文对 IVF 系列基线的比较)。PQ 后续还演化出更激进的 二值量化 (Binary Quantization) 和 标量量化 (Scalar Quantization)。
  • ScaNN (Scalable Approximate Nearest Neighbors) — Google Research 在 ICML 2020 论文《Accelerating Large-Scale Inference with Anisotropic Vector Quantization》中提出,2020 年 7 月开源 出处。ScaNN 通过 anisotropic vector quantization 在 glove-100-angular 基准上以两倍 QPS 领先于其他 11 个向量库,后续在 NeurIPS 2023 论文中又发布 SOAR 算法进一步提升 出处。ScaNN 是 Google Vertex AI Vector Search 的内核。

这段时期奠定了整个行业的算法基础:HNSW 主打高召回,IVF-PQ 主打内存压缩,ScaNN 主打 MIPS (Maximum Inner Product Search) 精度。

专用向量库崛起 (2021–2024):Pinecone 定义品类

2021 年,Edo Liberty (前 AWS SageMaker / Yahoo Research 负责人) 创办 Pinecone,首次将"向量数据库"作为独立产品类别推向市场,核心定位是 "long-term memory for AI" 出处。

多模 + 混合检索 + Serverless (2024–2026):从单一向量到混合智能

2024 年起,行业明显进入第三阶段:

  • 混合检索 (Hybrid Search) 成为默认:稠密向量 + 稀疏向量 (BM25) + 元数据过滤,几乎所有头部厂商 (Pinecone、Weaviate、Qdrant、Milvus 2.5、Snowflake Cortex Search、Oracle 23ai Hybrid Vector Index) 都将其作为标配 出处 (腾讯云 VectorDB 文档定义稠密+稀疏+RRF 重排)。
  • Serverless 化:Pinecone 在 2024 年推出 Pinecone Serverless,从 Pod 级手动扩缩容转向按用量计费;Weaviate、Qdrant 均推出无服务器或 Burst 模式。
  • 多模态:向量维度从 768/1536 (文本) 扩展到 1024/4096 (图像/视频),pgvector 0.7.0 通过 halfvec 支持 4000 维、bit 支持 64000 维 出处;Elasticsearch 8.19 支持 byte 量化 kNN 出处。
  • AI 集成检索 (Agentic Retrieval):Azure AI Search 2026 年 5 月推出 agentic retrieval (preview) — 让 LLM 分解复杂查询、子查询并行跑检索、提取 grounding data 出处。
  • 数据库厂商全面补位:Oracle 23ai、Postgres pgvector、Snowflake Cortex、Elasticsearch/OpenSearch、Amazon Aurora pgvector、华为 GaussDB Vector — 几乎所有主流数据库都把向量作为一等公民 出处。

关键概念词典

  • 向量索引 (Vector Index):HNSW (图)、IVF (倒排)、Flat (暴力) 三大族;为提升内存利用率还派生 PQ、SQ (Scalar Quantization)、BQ (Binary Quantization) 等压缩方法。
  • 量化 (Quantization):将 32-bit float 压缩到 8-bit (SQ)、4-bit、二值 (BQ) 以节省内存与加速距离计算 出处。
  • 分片 (Sharding):Milvus 通过 segment、channel、node 三级抽象支持水平扩展到十亿向量 出处;pgvector 则依赖 Citus / PgDog 等外部分片方案 出处。
  • 一致性 (Consistency):专用向量库 (Pinecone/Qdrant) 多为 eventual consistency,而 pgvector / Oracle 23ai 借助底层 RDBMS 提供 ACID 事务 出处。

HNSW（Malkov & Yashunin 2016/2018）— arxiv 1603.09320

维度 数据
arXiv 1603.09320 [555]
作者 + 机构 Yu. A. Malkov + D. A. Yashunin（俄罗斯 Nizhny Novgorod 应用物理研究所 / Yandex）
发表时间 v1 2016-03-30；v4 final 2018-08-14
关键贡献 Hierarchical Navigable Small World：多层 proximity graph，从顶层粗搜到底层细搜，实现 O(log N) 复杂度；用 exponentially decaying 概率选择元素层数；启发式邻居选择

为什么 HNSW 重要：HNSW 是 2016 以来 vector search 的"事实标准算法"。它把 NSW（2014）的 polylogarithmic 复杂度问题变成真正的 O(log N)，让 billion-scale ANN 成为可能。后续 DiskANN/Vamana、SPANN 都在 graph-based ANN 框架下延伸。[555]

Memory × VectorDB 融合趋势 (2026 H2)

核心论点

AI Agent 时代,Vector DB 不再孤立,而是与 Memory 层深度融合。Memory 层 = 短期 KV Cache(在 LLM context window 内的 attention KV 状态)+ 长期 Vector Store(Embedding 检索)+ 跨 Session Memory Graph(实体-关系结构化记忆)。

传统的"Vector DB 作为单一检索服务"的范式正在被三股力量重塑:

  1. LLM 厂商原生 Memory API — OpenAI Assistants vector_stores 对象(OpenAI 官方文档)、Anthropic Claude Memory(2025-09-11 推出,Team/Enterprise 优先,2025-10-23 扩展至 Pro/Max,Anthropic 官方公告)把 memory/检索做成模型 API 的"一等公民",挤压独立厂商中间层空间。
  2. Agent Memory 专业厂商崛起 — Mem0、Letta(前 MemGPT)、Zep 三个创业公司围绕 Agent 工作流的 long-term memory 形成新赛道,2024-2025 共融资超过 $35M。
  3. 框架层抽象 — LangGraph checkpointers 把"short-term(thread)+ long-term(store)+ semantic search"做成标准原语(LangGraph 官方文档)。

Agent Memory 三层架构 (Mem0 论文定义)

Mem0 团队 2025-04-28 在 arXiv 发表论文 "Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory"(arXiv:2504.19413,论文链接)提出增量式(incremental processing)memory 架构,将 Agent Memory 拆分为两层 pipeline:

  • Extraction phase:从对话消息对中提取 salient facts;
  • Update phase:基于已有 memory store 和对话摘要 S 决定 ADD/UPDATE/DELETE 操作。

该论文还提出 Mem0^g 变体——在自然语言 memory 之上叠加 Graph Memory(三元组 (v_s, r, v_d) 表示实体关系),在 LOCOMO 基准上 F1=51.55、J=58.13(arXiv HTML)。

框架层抽象 (LangChain / LlamaIndex / LangGraph)

LangGraph(LangChain 旗下)提供三层 Memory 原语,设计哲学是"在 state graph 上做时间旅行":

  • Short-term(线程级):通过 InMemorySaver / SqliteSaver / PostgresSaver 等 checkpointers 实现(LangGraph 文档);
  • Long-term(用户/应用级):通过 InMemoryStore + 嵌入模型实现语义检索 memory(Memory 文档);
  • 持久化中间件:encrypted serde、async/await 支持、K8s 友好的无状态图。

LlamaIndex 提供 ChatMemoryBuffer + VectorMemory 抽象,把对话历史自动转 embedding 入库,与 RAG pipeline 复用同一向量索引。

关键意义:框架层让 Memory 抽象标准化——开发者不必关心底层到底是 Postgres、Redis、还是 Pinecone;这也推动了 Memory-as-a-Service 的"可插拔"基础设施层出现。

CXL 内存池化对 Vector DB 性能的影响

CXL(Cache/Coherent/Memory Link)3.0 在 2025-2026 年完成首批商业部署,核心能力是内存池化(memory pooling)+ 解耦内存(composable memory)。

对 Vector DB 的关键影响(基于 Samsung CMM-D 白皮书 2026-06):

  • CXL switch-based memory pool 在 TP=1 单 GPU 配置下作为 LMCache 后端,性能接近 DRAM;
  • 在 TP=8 多 GPU 配置下,达到 DRAM 的 ~92.3%(47 GB/s 带宽实测);
  • 1TB CXL pool(1 USP–4 DSP 拓扑)在 KV cache 120 documents 场景下,TPS 稳定 ~354K,与 512GB DRAM 表现相当。

结论:Vector DB 的 hot index(常用向量)仍放 DRAM,但 cold-tier embedding / 大规模 ANN index 可以下沉到 CXL memory pool,$/TB 显著下降(业界估算 30-60%),使数十亿向量级别的索引成本可控。这是 MemVerge / XConn / Samsung 联合发力的方向(详见 §4.4 / §4.7)。

定义:JEDEC JESD328 标准下的"Small Outline CAMM2"模块,把笔记本 LPDDR5X 引入服务器,以可拆卸 connector 设计取代焊接。

NVHBM — NVIDIA 自定义 HBM(8-layer, Rubin Ultra 起步)

定义:NVIDIA 2026-08-26 公开 NVHBM 规范,把 HBM base die 内的 memory controller 设计收回自家(原属 memory 厂商),并与 NVLink Fusion 互联体系绑定(Digital Today 报道)。

关键设计变化(三星 8-layer 版本, Seoul Economic Daily):

  • stack 从 12/16 层降到 8 层(制造良率压力骤减);
  • pin speed 从 14.4 Gbps 提升到 17-18 Gbps(>20% 提升);
  • 控制器逻辑嵌入 HBM base die,带宽 +30%、HBM 功耗 -15%、XPU die area +25%(NVIDIA 官方数据,未第三方验证)。

Rubin Ultra 应用:

  • Rubin Ultra NVL576 规模达 576 GPU/rack,GPU 间互连扩大 8 倍(72 → 576);
  • 单 rack 总 fast memory 达 365TB,远高于 Rubin NVL144 的 75TB(Tom's Hardware)。

供应链含义:三星因拥有 DRAM+逻辑 base die(4nm foundry)端到端能力,在 NVHBM 早期拿下一席;SK hynix、Micron 跟进。TrendForce 2026 Q3 报道 NVIDIA 调整 Rubin Ultra 配置,因 DRAM 短缺而评估用 HBM4e 8hi、HBM4 12hi、HBM4 8hi 等降级替代方案(Gate News)。
