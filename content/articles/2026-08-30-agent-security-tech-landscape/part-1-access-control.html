访问控制:Agent 的「门禁」系统

当一个 Agent 拥有「长期 Token、跨 SaaS 写权限、Tool 调用能力」时,传统 IAM 体系 (Identity & Access Management, 身份与访问管理) 就必须被重写。本章剖析 MCP、OAuth for AI、 Astrix、Reco AI、Nudge Security、CSA Agentic AI 工作组,以及「影子 AI」这个新战场。

1.1 问题的本质:谁来给非人类发 Token?

过去十年,身份管理的对象是人类(用户)与服务(API Key)。2024 年起,第三个对象登场: Agent——一个有持久身份、长期 Token、跨多 SaaS 写数据权限的「软件人」。 Astrix Security 在 2024 年 12 月的 B 轮融资公告中,把这种对象称为 NHIs (Non-Human Identities, 非人类身份)。 [来源: Astrix News, 2024-12-10]

NHIs 不只是 API Key 的别名。它的特征:

  1. 长期身份:OAuth Refresh Token 可能 30 天有效,Agent 凭此「随时上班」。
  2. 代理性:代表用户行事,但权限边界由谁决定并不清晰。
  3. 跨域漂移:同一 Agent 可能在 Salesforce、GitHub、Slack 各自拥有不同权限。
  4. 链式调用:Agent A 调用 Agent B,后者再调用 Tool,审计追踪断裂。

这意味着 IAM 体系要从「用户-角色-权限」三元组,扩展为「用户-角色-权限-Agent-Tool-资源」六元组。 Cloud Security Alliance 在 2025 年发布的 Agentic AI Risk Framework 把这一转型列为核心议题。 [来源: CSA Blog, 2025-02]

1.2 MCP:Model Context Protocol 的崛起与隐患

MCP (Model Context Protocol) 由 Anthropic 于 2024 年 11 月开源,目标是「让 Agent 标准化地连接工具与数据源」。 截至 2026 年 8 月,MCP 已成为事实标准:OpenAI、Google DeepMind、Microsoft Copilot Studio、Block、Replit 等都已宣布原生支持。 [来源: modelcontextprotocol.io 官方]

MCP 的核心是 JSON-RPC over stdio/HTTP/SSE,客户端(MCP Host,如 Claude Desktop)通过 MCP Client 连接 MCP Server(暴露 Tool)。每次 Tool 调用,Client 都会附带用户的 OAuth Token 或本地凭据。

「MCP 把 Agent 与 Tool 的连接做成了 USB-C:任何 Tool 都能即插即用。但 USB-C 不解决「该不该插」的问题——这恰恰是 IAM 的工作。」 — Ivana Bartoletti, Wiz 首席隐私官, RSA Conference 2025 演讲(2025-04-28)

MCP 在 2025 年 11 月被 OWASP Top 10 for LLM Applications 2025 版 单独列为 LLM05: Improper MCP Server Sandboxing & Validation,提示四大类风险:

  • Tool 名称冲突:MCP Server 之间没有命名空间,同名 Tool 会覆盖。
  • Tool Poisoning:恶意 MCP Server 在 description 字段藏 prompt injection。
  • Rug Pulls:MCP Server 运行时替换 Tool 实现,前 100 次调用安全,第 101 次写恶意代码。
  • Token Leakage:OAuth Token 通过 MCP 调用泄露到下游 Tool。

[来源: OWASP LLM Top 10, 2025 版]

1.3 OAuth for AI:IETF 的最新尝试

2024 年 12 月,IETF Secure Authentication for Everyone (SAFE) 工作组发布 draft-ietf-safe-ai-agent-auth 草案,提出 AI Agent Identity Assertion (AIA) 概念。 它在 OAuth 2.0 的基础上新增 agent_id、principal_user、delegation_chain 三个字段。 [来源: IETF Datatracker]

截至 2026 年 8 月,该草案仍在 IETF 99 (2026-06) 后的小组审阅阶段,尚未成为 RFC。 主要争议:

  • 代理链深度:Agent A → Agent B → Agent C,审计追踪何时「压缩」?
  • 撤销语义:User 撤销授权时,Agent 已发出但未到达的请求是否「撤回」?
  • 人机混用:Agent 自主决策时,「用户意图」如何记录?

1.4 三大独角兽:Astrix / Reco / Nudge

独角兽Astrix Security · 影子 AI 与 NHI 治理

总部:以色列 Tel Aviv + 纽约 · 成立:2021 · 创始人:Alon Jackson(Co-founder & CEO,前 Cybereason、IDF 8200)、Idan Gour(Co-founder & CTO,IDF 8200)

融资:2024-12-10 Series B $45M,由 Menlo Ventures 通过其 Anthology Fund(与 Anthropic 战略合作基金)领投,Workday Ventures、Bessemer Venture Partners (BVP)、CRV、F2 Venture Capital 跟投。累计 $85M。 [来源: SecurityWeek, 2024-12-10]

核心技术:

  • NHI Discovery:通过云 API 审计 + DNS 流量分析,发现所有非人类身份的「影子 NHI」(类似 Shadow IT 的 AI 版本)。
  • Posture Management for AI:把 IAM 权限图谱映射到 Agent / Tool,自动标记「超权 Agent」。
  • AI Agent Trust Layer:对 Agent 的 Tool 调用实时评分,异常行为自动 quarantine。

盈利模式:SaaS 订阅(企业版 $60K-$300K/年)+ 数据集成费(每接入一个云厂商 ~$20K)。 客户:Workday、Microsoft、Palo Alto Networks、自家集成生态。

Astrix Security 平台架构(NHI Security Platform Built for AI Agents,2024-12-10 Series B $45M Menlo Ventures):

  • 3 大产品线:Discover / Secure / Deploy
    • Discover:AI Agent + NHI 单一清单,自动化发现所有 agent(自定义 / 第三方 / homegrown),含 shadow / 未注册 agent
    • Secure:识别过度权限 agent / 漏洞配置 / 异常活动 / 策略违规,自动修复
    • Deploy:'Secure by design' 部署,least-privileged + 完整审计 trail + short-lived credentials + JIT access
  • 5 大能力:
    • Complete Visibility — 自动识别 + 映射每个 AI agent + 关联 NHI + 权限 + 访问环境
    • Third-party Exposure Identification — 快速发现未授权的外部 AI agent + 集成
    • Proactive Risk Scoring — 基于暴露 / 配置漏洞 / 权限敏感度的优先级排序
    • Advanced Privilege Management — 检测 + 修复冗余 / 过度权限 / 非活跃 / 孤立 agent
    • Secure Authentication Practices — 修正 static credential 等不安全实践
  • Ownership Clarity + Lifecycle Management:每个 AI agent 映射到人类 stakeholder;基于策略的 onboarding;credential 生命周期管理
  • Proactive Threat Detection:实时行为监控,异常检测;compromised agent 立即响应
  • Posture Management + Agent Access Policy:Granular identity-based access policies,scoped by user / department / platform / resource type,action 执行前 evaluate
  • Agentic Threat Detection & Response (ATDR):检测 compromised credentials / 异常访问模式 / 越权 agent 行动
  • Threat Center:统一威胁检测 + 响应中心,合并碎片化告警为优先级 Threat Cases
  • 数据源:cloud / SaaS / on-prem / databases / Vaults / CI/CD / AI platforms 跨数据源关联
  • AI Agent Identity Graph:核心 — 用户 + service account 数据融合的 Identity Graph,识别 shadow agent + owner

关键数据点:

  • 80% 企业:AI agent 出现 unintended actions(包括下载敏感内容)
  • 50% 企业:经历 confirmed or suspected cyber incident 由 AI agent 导致
  • 100:1 比例:AI Agents + NHIs vs humans 数量比
  • 99% 身份未治理:agents + NHIs 仍处于 IAM + 审计周期之外

独角兽Reco AI · SaaS 工作流与 AI 应用治理

总部:以色列 · 成立:2020 · 创始人:Gal Nakash(前 AlgoSec CTO)

融资:2026-02-10 Series B $30M,由 Zeev Ventures 领投,Insight Partners 跟投;累计 $55M+。 [来源: Reco Blog, 2026-02-10]

核心技术:

  • 影子 SaaS 与影子 AI 发现:从 IdP 日志 + 浏览器代理 + OAuth 授权事件,反推「哪些用户在用哪些 AI 工具」。
  • 业务上下文图谱:用知识图谱把「Salesforce 字段 → AI 工具 → 输出目的地」串起来,自动识别「含 PII 的 AI 调用」。
  • 动态访问控制:对高风险 SaaS 工具实施「Just-in-Time」授权,Token 10 分钟过期。

Reco 平台架构(Agent Ecosystem Security Platform,2026-02 Series B $30M Zeev Ventures):

  • 8 大产品线:
    • Reco Factory:No-code 引擎,几天(非几个月)连接新 SaaS
    • Application Discovery:持续监控新应用出现,含 shadow AI/Shadow SaaS
    • Identity Access Governance:映射每个 identity,最小化每个 privilege,zero-trust 跨集成应用
    • Posture Management & Compliance:即使环境持续变化,合规不掉
    • Threat Detection (ITDR):数百个 pre-built 检测控制,数据盗窃 / 账户妥协 / 配置漂移
    • Data Exposure Management:跨 agent + app 生态系统的数据暴露风险识别
    • AI Governance and Security:从 ChatGPT 到 copilots 全治理
    • Agentic Security Posture Management(2025-Q4 新增):AI agent 处理威胁狩猎 + 策略执行
  • 多信号源发现:SSO logs + email metadata + OAuth integration monitoring + behavioral analysis — 4 类信号融合
  • 动态知识图谱:apps / AI tools / users / data flows 之间连接,完整 attack surface 视图
  • 分类引擎:自动给每个 app + AI agent 标签 — sanctioned/unsanctioned + function + sensitivity + business impact
  • Identity Intelligence:user → application + AI agent 映射,揭示隐藏权限 + 风险访问模式
  • 覆盖:approved tools → hidden ChatGPT/Claude usage,multi-sensor behavioral analysis

关键数据点:

  • 500+ SaaS 应用:平均企业使用 500+ SaaS,其中 90% 未管理
  • 15-20 个 app/天:CISO 平均每天要决定 sanction 15-20 个 app(来源:Neda Pitt, CISO)

盈利模式:SaaS 订阅(每 SaaS 集成 $5K/年)+ 企业版按数据量计费($100K-$500K/年)。

独角兽Nudge Security · AI 治理与员工行为

总部:美国 Austin, TX · 成立:2022 · 创始人:Russell Spitler(前 AlienVault / AT&T Cybersecurity 创始人)、Jaime Blasco

融资:2025-11-18 Series A $22.5M,由 Cerberus Ventures 领投,AWS ISV 加速基金跟投。 累计约 $30M。 [来源: Nudge Blog, 2025-11-18]

核心技术:

  • 员工级 AI 工具追踪:从 OAuth 授权事件反向追踪「这个员工授权了哪些 AI 工具」。
  • 「Nudge」行为引导:当员工在 ChatGPT 粘贴敏感代码时,自动弹 Slack 提示「请改用公司 Copilot」。
  • AI 工具风险评分:基于数据集来源、隐私政策、历史泄露事件自动打分。

Nudge Security 平台架构(员工级 AI 治理先驱,2025-11 Series A $22.5M Cerberus Ventures):

  • 核心机制:SaaS OAuth 授权事件流 → 反向映射每个员工的 AI 工具栈 → 实时 nudge 行为
  • 3 大能力维度:
    • 可见性:员工 → 工具栈 → 风险评分 全链路映射
    • 行为引导:Slack/Teams 内嵌的「轻推」,改变员工 AI 使用习惯
    • 合规:自动给工具打分,识别高风险 AI 工具,协助 compliance
  • 3 步工作流:
    • Step 1:观察 — 员工授权了哪些 AI 工具(无 agent / 无 EDR 部署)
    • Step 2:评分 — 基于数据集来源、隐私政策、历史泄露事件自动打分
    • Step 3:引导 — 当员工高风险行为时,Slack 内实时 nudge,引导到公司 Copilot
  • 特色:零代理部署:不需在终端装 EDR / agent,纯靠 SaaS OAuth 事件,几分钟内可见全公司 AI 使用图谱
  • 创始人背景:Russell Spitler(AlienVault / AT&T Cybersecurity 创始人) + Jaime Blasco(AT&T CSO) — 出身传统 SOC 自动化
  • 对比 Astrix / Reco:
    • Nudge:员工视角 + 行为引导 + SaaS 优先
    • Astrix:Agent / NHI 视角 + 身份治理 + 全云覆盖
    • Reco:业务视角 + SaaS 生态 + 数据流

盈利模式:每员工每年 $15-$30 + 企业版按 SaaS 集成数计费。

1.5 CSPM/SIEM 视角下的「Agent 身份」

传统 CSPM(Cloud Security Posture Management, 云安全态势管理)如 Wiz、Orca Security 已经支持扫描「IAM 角色过度授权」,但对 Agent 的支持仍在追赶。Wiz 在 2025 年被 Google 以 $32B 收购后,正在把 AI Agent 资产纳入其 AI Security Posture Management (AI-SPM) 模块。 [来源: Wiz Blog]

Microsoft Defender for Cloud 在 2025-09 推出的 AI Workload Protection 同样把 Agent 视为一种 workload,在 Entra ID (Azure AD) 中以 Workload Identity 的形式管理。 [来源: Microsoft Learn]

1.6 未突破的难题

  1. 「Agent 离职」语义缺失:User 撤销授权后,Agent 在远端缓存的中间状态、已完成但未审计的 Tool 调用, 没有标准化的「撤销协议」。
  2. 链式调用的责任划分:Agent A 调用 Agent B,后者泄露数据——法律责任归 A 还是 B?现行法规(CFAA、GDPR) 未明确。
  3. Tool Poisoning 检测滞后:MCP Server 在 description 字段藏 prompt injection, 现有 SCA(Software Composition Analysis, 软件成分分析)工具看不到 LLM 字段,必须专用扫描器。
  4. 合规审计不可行:SOC 2 / ISO 27001 框架假设访问决策由人做出,Agent 自主决策时 「授权来源」字段为空。
  5. 跨云 NHI 联邦:同一 Agent 在 AWS IAM、Azure Entra、GCP Service Account 三套身份体系中的「主身份」是什么? 目前无标准。

1.7 现场事故:两次 Agent 权限事故

事故 1:ChatGPT 插件 OAuth Token 大规模泄露(2024-06)

2024 年 6 月,Slack 通过 ChatGPT 插件 OAuth 集成的 Token 因 ChatGPT 端 prompt injection 而泄露, 攻击者可读取 Slack 频道历史。Slack 紧急禁用了插件,所有用户重新授权。 [来源: SecurityWeek, 2024-06]

事故 2:Cursor IDE 的 Auto-Run 模式写入恶意文件(2025-08)

2025 年 8 月,Anthropic 的 Cursor IDE 在 Auto-Run 模式下,因 prompt injection 让 AI 写入了 一个恶意的 .bashrc,导致开发者环境被植入持久后门。Cursor 团队在 v0.42 中加入了 「危险命令二次确认」,但仍未解决「Agent 自行决定执行」的根问题。 [来源: Cursor Security Advisories]
