CH.01维度一: Agent 核心架构与工具调用管道

Hermes 的核心设计是 多进程 Agent Runtime + 工具沙箱 + ReAct 循环。本节基于源码深度剖析其消息状态机、结构化输出引擎与端到端调用链。

1.2 对话循环 (ReAct / Conversation Loop)

agent/conversation_loop.py 实现 ReAct 思考步进。核心函数 run_conversation 节选:

def run_conversation(
    agent, user_message, system_message=None, conversation_history=None,
    task_id=None, stream_callback=None, moa_config=None, turn_author=None
) -> Dict[str, Any]:
    """Run one turn (see ``_run_conversation_turn``) and export the current-turn boundary.
    Every envelope that leaves the loop — success, partial/error, interrupt,

    """
    from agent.turn_context import export_current_turn_boundary
    from tools.vision_tools_history_budget import native_turn_images

1.2.1 Turn Context + Turn Recovery

turn_context.py 维护 turn state, turn_recovery.py (103KB) 实现自愈机制 — 当 Tool 调用失败时, 通过 reflection retry + context 裁剪恢复。

1.3 Tool Calling 管道

tool_executor.py (95KB) 是 Tool dispatcher: 接收 LLM 结构化输出, 解析 tool_call, 路由到对应 tool 实现, 收集结果回填。

1.4 结构化输出与 JSON Schema 校验

auxiliary_structured_output.py 实现 JSON Schema 约束校验, 配合 LLM 的 tool_use 协议, 确保 tool_call 参数符合预期 schema。

1.5 Adapter 层

Hermes 支持多 Provider 通过统一抽象: AnthropicAdapter, CodexAdapter, BedrockAdapter, GeminiNativeAdapter。每个 adapter 内部处理 message format 转换 (Anthropic MessageConvert)。

1.6 End-to-end 调用链

一次完整的 Hermes Agent 调用流程:

User Input → cli.py / run_agent.py
  ↓ init_agent (agent_init.py)
  ↓ setup toolsets (toolsets.py)
  ↓ prompt_builder assembles (prompt_builder.py + system_prompt.py)
  ↓ LLM call via auxiliary_client (Anthropic/OpenAI/Bedrock)
  ↓ tool_call parsed via auxiliary_structured_output
  ↓ tool_executor dispatches
  ↓ tool executes in sandbox (terminal_tool / browser_tool / file_ops)
  ↓ observation backfilled
  ↓ turn_context updated, turn_recovery may retry
  ↓ loop until finish_reason or max_iterations
  ↓ hermes_state_messages persists (WAL)
  ↓ response to user

CH.02维度二: 核心关键技术原理与代码机制

2.1 Prompt 模板与 Special Tokens

agent/system_prompt.py (47KB) 实现 Hermes 特有的 ChatML 扩展 + Tool Call Tokens, 防止模型在多轮工具调用中出现格式崩塌。

agent/prompt_builder.py (108KB) 是 Hermes 最大的 Prompt 模块, 实现 Dynamic Prompt Assembly: 上下文感知的 Tool 描述注入、Few-shot 示例选择、用户偏好注入。

2.2 错误纠正与自愈机制 (Self-Correction)

agent/turn_recovery.py (103KB) 实现执行环境报错时的反射重试与 Context 裁剪策略。包含: retry 计数、错误分类、超时检测。

错误类型自愈策略
JSON 语法错误反射重试 + 上下文注入 schema 示例
类型不匹配重新解析 + 类型转换 (arg_coercion.py)
工具超时指数退避 + 缩减 max_iterations
Provider 不可用auxiliary_health.py → auxiliary_fallback_recovery.py 切换
Auth 失败credential_pool.py 自动轮转

2.3 多轮会话状态持久化与 Context 动态压缩

Hermes 用多层 State 系统实现持久化:

  • hermes_state_messages.py (107KB) — 消息历史 WAL
  • hermes_state_wal.py — Write-Ahead Log, 崩溃恢复
  • hermes_state_sessions.py — 会话生命周期管理
  • hermes_state_compression.py — 状态压缩
  • hermes_state_lockguard.py — 并发控制
  • hermes_state_lockowners.py — Lock owner tracking

2.3.1 Context 压缩

context_compressor.py (324KB) 与 conversation_compression.py (248KB) 实现上下文压缩: 长工具返回截断、token budget 分配、micro-compaction (post-turn)。

2.3.2 Memory

memory_manager.py (46KB) 提供跨会话记忆: short-term (当前会话) / long-term (持久化) / RAG (向量检索)。

2.4 Checkpoint 机制

tools/checkpoint_manager.py 实现 Agent 状态 checkpoint: 在 turn 边界保存 (state, messages, tools), 支持回滚与恢复。

2.5 Trajectory 压缩

trajectory_compressor.py 处理训练用 trajectory: 压缩、标注、tokenize, 用于 RLHF/DPO 数据准备。

2.6 Mixture-of-Agents (MoA)

agent/moa_loop.py (78KB) 实现多 Agent 协同: 多个 Agent 同时运行, 通过投票或加权融合生成最终结果。

CH.03维度三: API 规范、生态接口与周边改造切入点

3.1 对外 API 与 Tool Runner SPI

3.1.1 MCP Server (Model Context Protocol)

mcp_serve.py 实现 MCP 协议, 让其他工具/Agent 可以作为 MCP Server 接入 Hermes。Anthropic 推动的标准协议, 用于工具互操作。

3.1.2 Toolsets

toolsets.py 定义可插拔工具集: 用户可启用/禁用, 提供权限分级。

3.1.3 Model Tools

model_tools.py 注册模型特定的工具支持, 例如 Claude 3.5 Sonnet 支持 computer_use, GPT-4o 支持 vision。

3.2 沙箱执行环境集成

3.2.1 Terminal Tool

tools/terminal_tool.py 提供 Shell 执行能力。当前是进程级隔离, 可以接入 E2B / Firecracker MicroVM 改造为 VM 级沙箱。

3.2.2 Approval 机制

tools/approval.py (70KB) + tools/approval_detection.py (90KB) 实现 Human-in-the-loop: 自动检测风险命令, 暂停执行, 等待用户确认。

3.3 Browser / File Tool

tools/browser_tool.py (Playwright) 提供浏览器自动化, tools/file_operations.py 提供 FS 沙箱。

3.4 外挂记忆与 RAG 检索钩子

plugins/plugin_loader.py + plugins/memory/ 目录: 18 个 plugin 其中 memory plugin 提供 RAG 接入点。

3.5 MCP OAuth 与异步委托

tools/mcp_oauth.py 处理 MCP 协议 OAuth 流程, tools/async_delegation.py (66KB) 实现子 Agent 委托 (sub-agent spawning)。

3.6 推理引擎联动 (vLLM / SGLang Prefix Caching)

agent/chat_completion_helpers.py (222KB) 是 Hermes 与推理引擎的桥接层: 通过 OpenAI 兼容 API 调用 vLLM / SGLang。

CH.04维度四: 系统瓶颈、局限与前沿演进预测

4.1 代码级瓶颈与技术债务

4.1.1 State 锁竞争

hermes_state_lockguard.py + hermes_state_lockowners.py 实现并发控制, 但全局 lock 在 100+ 会话下会串行化 State mutation。

4.1.2 Auxiliary Client 降级链

auxiliary_health.py, auxiliary_fallback_recovery.py, auxiliary_unavailable.py: 多 Provider (Anthropic → OpenAI → Azure) 切换链路长, retry storm 可能。

4.1.3 MCP / IPC 序列化

mcp_serve.py 用 JSON-RPC over stdio/HTTP, 序列化开销大。

4.2 前沿演进预测

4.2.1 多模态工具调用

预测路径: 2026 H2 - 2027 H1. 现状以文本 Tool Call 为主, 演进方向: 图像/音频/视频作为 Tool Call 参数。

4.2.2 动态代码解释器 (MicroVM Sandbox)

预测路径: 2026. 接入 E2B / Firecracker MicroVM, 隔离执行。

4.2.3 自进化 Agent 编排

预测路径: 2027. agent/moa_loop.py 静态权重 → RLHF/CSPO 在线学习。

4.2.4 Hermes ↔ vLLM/SGLang Native 联动

预测路径: 2026. Hermes Native API 直接与 vLLM/SGLang Prefix Cache 协同, 透传 prefix hash 最大化 Agent 多轮 prefix 命中率。

4.2.5 Agent-to-Agent (A2A) 协议

预测路径: 2027. tools/async_delegation.py 子 Agent 委托 → A2A 标准化。
