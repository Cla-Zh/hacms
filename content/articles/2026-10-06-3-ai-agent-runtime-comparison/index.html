CH.01架构哲学与定位差异

三个项目虽然都被贴上 "AI Agent" 标签，但核心设计哲学截然不同。本章节通过 7 个核心问题对比，回答 "为什么三个项目的架构差异这么大"。

1.1 一句话哲学对比

项目哲学原始表述
Hermes Agent"会成长的心智" (Self-improving)"The only agent with a built-in learning loop — it creates skills from experience, improves them during use, nudges itself to persist knowledge, searches its own past conversations, and builds a deepening model of who you are across sessions" — README L19
OpenClaw"你设备上的、你的、连接一切的" (Local, yours, everywhere)"OpenClaw is an open-source AI assistant that runs on your own computer and meets you in the channels you already use... State, memory, and credentials live on your hardware. Models and agent harnesses (Claude, Codex, local models) are plugins you can swap without changing anything else" — README L18
DeepSeek Harness"一切皆插件" (Plugin-all-the-way)"Everything is a Plugin" — deepseek-ai/deepseek-harness README

哲学差异决定了一切后续架构选择。Hermes 把"学习"作为一等公民；OpenClaw 把"用户主权"作为一等公民；DeepSeek 把"可组合性"作为一等公民。

1.3 核心问题 2：运行模式 — Per-task vs Always-on

Hermes Agent: Per-task invocation

  • 每次调用创建一个新的 AIAgent 实例（agent/agent_init.py:51-52 注释: "the gateway builds a fresh AIAgent per message"）
  • 没有"长期驻留进程"概念 — 每次 turn 是一次独立的 LLM 调用循环
  • 通过 gateway daemon（hermes_gateway）对外接受 Telegram/Discord 消息，但每次消息都 spawn 一个新的 AIAgent

OpenClaw: Always-on daemon

  • src/daemon/ 目录 267 个 .ts 文件
  • openclaw gateway start 启动一个长期运行的 daemon
  • daemon 持续监听 IM 通道、维护 session、处理消息
  • 类似 systemd / launchd 的服务进程模型

DeepSeek Harness: Profile-based composition

  • 既支持 CLI 一次性调用（dsh run "task"），也支持 web GUI 长期会话
  • dsh-base bundle 包含 100+ plugins（composition.md），由 cordis.yml 描述
  • 不同 profile（web / headless / sdk / acp）patch 同一 base bundle

来源:

  • Hermes Agent Architecture
  • OpenClaw Gateway 架构
  • DeepSeek Harness Architecture

1.4 核心问题 3：代码组织 — 单体 vs Monorepo

Hermes Agent: Python 单体 + 模块化目录

hermes-agent/
├── agent/             # 265 .py - 核心 agent runtime
├── hermes_cli/        # 120+ .py - CLI 子命令
├── hermes_core/       # 100+ .py - gateway / session / skills
├── hermes_plugins/    # 50+ .py - 扩展点
├── acp_adapter/       # 14 .py - ACP 协议适配
└── ...

优点: 单进程部署简单，单一 import 路径（from agent.X import Y）。

缺点: 任何模块改动都要重启整个进程；版本管理是 Python 包的版本。

OpenClaw: pnpm monorepo + 多端原生

openclaw/
├── apps/
│   ├── macos/Sources/         # Swift
│   ├── ios/Sources/           # Swift
│   ├── android/app/           # Kotlin/Dart
│   ├── linux/                 # TS
│   └── shared/                # 共享库 (OpenClawKit, etc.)
├── src/                       # 核心 TS daemon (8万行)
└── ...

优点: 单一版本号管理多端；新平台只需新增 apps//。

缺点: 编译时间长（Swift + Kotlin + TS）；首次 build 需要 30+ 分钟。

DeepSeek Harness: pnpm monorepo + 60+ packages

deepseek-harness/
├── apps/{cli,web,desktop,desktop-host}/  # 4 个 app
├── packages/                # 60+ 包
│   ├── core/                # 8 包 (session/tools/agent/agent-loop/...)
│   ├── llm/, sandbox/, skill/, subagent/, ...
│   ├── extensions/, mcp/, hooks/, ...
│   └── experimental/        # 预发布原型
├── bundles/                 # 可组合 bundle
└── ...

优点: 极致可组合性 — dsh-base 是 100+ plugins 的组合，可以 patch 任意子集。

缺点: 维护成本高 — 60+ packages 都要维护 README、AGENTS.md、tests。

来源:

  • OpenClaw pnpm workspace — "The repository is a pnpm workspace"
  • DeepSeek Harness Packages Map — 60+ packages 列表

1.5 核心问题 4：扩展模型

Hermes Agent: Python module plugin

  • 通过 hermes_plugins/ 目录加载
  • Plugin 形式: Python 模块，导出特定 hooks
  • 例如 memory_provider.py 定义 MemoryProvider 接口，多个第三方实现可注册
  • 自动发现机制：hermes_cli/plugins.py 的 PluginManager

OpenClaw: TypeScript plugin via plugin SDK

  • 官方 plugin SDK
  • Plugin 通过 npm 包发布到 ClawHub
  • 模型、agent harness 都可以替换 — "Models and agent harnesses (Claude, Codex, local models) are plugins you can swap without changing anything else"

DeepSeek Harness: Cordis plugin

  • 基于 cordiverse/cordis 元框架
  • "A Programming Paradigm for Spatiotemporal Composability"（Cordis 学术论文）
  • 三层分离: Service Definition / Service Provider / Consumer
  • 插件通过 cordis.yml 注册，runtime 通过 cordis load 装载
  • HMR（Hot Module Reload）支持 — 见 dsh-hmr plugin

来源:

  • Cordis GitHub — 8.8k stars
  • Cordis 学术论文 (arXiv)
  • Capability Seams 架构原则

CH.02核心循环与工具调度机制

Agent 的核心是 循环（loop）——一次 turn = 一次 model call + 工具 dispatch + 状态更新。三个项目的循环设计反映了完全不同的工程哲学。

关键设计：_ra patch contract

agent_runtime_helpers.py 提供 _ra() 函数，让 run_agent 命名空间下的 monkey-patch 仍然生效 — 这样测试可以在不改源代码的情况下替换关键函数。

# agent/agent_runtime_helpers.py 概念
def _ra(name):
    """Resolve a symbol via run_agent.* so monkey-patch from tests works."""
    return getattr(__import__("run_agent"), name)

来源: agent/agent_init.py:7 注释: "Symbols that tests patch on run_agent.* (OpenAI, get_tool_definitions, logger, …) are resolved through :func:_ra so the patch contract is preserved."

2.3 OpenClaw 的 auto-reply 三层调度

OpenClaw 的 turn loop 入口在 src/auto-reply/，核心抽象是 chunk —— 一个 chunk = 一次 IM 消息的多个 segment（text / image / tool call / attachment）。

三层调度

  1. chunk 解析 (chunk.ts / chunk.plugin-runtime.test.ts): 把 IM 消息拆成可处理的 segments
  2. command auth (command-auth.ts / command-control.ts): 验证用户是否有权限执行 command（DM-capable channels 默认 pair 未知用户）
  3. command detection (command-detection.ts / command-turn-detection.ts): 识别是否是 slash command、是否走 agent loop、还是走 direct reply

    4. 来源:

    • src/auto-reply/chunk.ts — 111 个 .ts 文件
    • src/commands/ — slash command registry
    • src/daemon/cmd-set.ts — daemon 命令集合

    与 Hermes 的关键差异

    OpenClaw 不是 agent loop, 而是 message dispatcher。它把消息路由到:

    • Direct reply（无需 LLM）
    • Slash command（无需 LLM）
    • Agent harness（Claude Code / Codex / 本地模型 — 由 plugin 决定）
    IM Message → channel adapter → chunk parser → 
  → auth check → command detection

    2.4 DeepSeek Harness 的 Event Sourcing Projection

    DeepSeek Harness 使用 Event Sourcing 模式管理会话状态 —— 每次 turn 是一串 events 追加到 session log，再由 projection 派生出当前 UI 状态。

    核心 packages

    • packages/scope/: scoped registration primitive
    • packages/session/: append-only session event log (ctx.sessions)
    • packages/system-prompt/: system prompt 装配
    • packages/tools/: tool registry + guarded execution pipeline
    • packages/agent/: Agent handle + live registry (ctx.agents)
    • packages/agent-loop/: default agent driver (swappable) (ctx.agentLoop)
    • packages/agent-default-model/: deployment default model

    来源: packages/core/README.md — "Product API spine: sessions, prompts, tools, agent services, and the concrete loop"

    Session Event Sourcing 示例

    // packages/session 概念
// 每次 turn 追加 event 到 JSONL log
session.append({ type: 'user_message', content: 'fix bug' });
session.append({ type: 'tool_call', tool: 'read_file', args: {...} });
session.append({ type: 'tool_result', result: '...' });
session.append({ type: 'assistant_message', content: 'fixed' });

// Projection 派生 UI 状态
const projection = sessionQuery.project(sessionId);

    来源: packages/session/README.md — "The durable session data plane: persistence seam + backends, projection seam, log-backed titles, session reporting"

4.2 Hermes 的子代理：RPC + 脚本调用

Hermes 的设计哲学是 "让子代理像 Python 函数一样调用"：

# 概念: tools/delegate_tool.py
async def delegate_task(subagent_type, prompt, context=None):
    """Spawn an isolated subagent for parallel work."""
    subagent = create_subagent(subagent_type)
    result = await subagent.run(prompt, context)
    return result

调用方式:

# 主 agent 决定并行处理
results = await asyncio.gather(
    delegate_task("researcher", "research X"),
    delegate_task("coder", "implement X"),
)

来源:

  • Hermes Agent Architecture — Subagents
  • tools/delegate_tool.py

Hermes 的差异化: "Write Python scripts that call tools via RPC, collapsing multi-step pipelines into zero-context-cost turns" — 子代理可以写脚本调用工具, 而非必须经过 LLM。 这是 Hermes 独有的 "zero context cost" 优化。

4.3 OpenClaw 的子代理：抽象层

OpenClaw 不直接实现子代理 — 它依赖具体的 agent harness 决定。Claude Code / Codex / Hermes 等都可以作为 OpenClaw 的子代理后端。

interface AgentHarness {
    runTurn(prompt: string, context: Context): Promise;
    delegate(agentType: string, task: Task): Promise;
}

// Claude Code harness implements AgentHarness
// Codex harness implements AgentHarness

来源: OpenClaw Plugin SDK — "Models and agent harnesses (Claude, Codex, local models) are plugins"

4.4 DeepSeek Harness 的子代理：Capability Family

DeepSeek 的设计最严谨 — 子代理作为 capability family:

packages/subagent/
├── provider-registry    # Service Definition
├── delegation-tools     # model-facing tools
└── ...

设计哲学: DeepSeek 把 subagent 看作 第一公民的 capability, 不是辅助工具。agent-default-model 拥有 default selection policy, subagent 有自己的 registry, 这是 capability-driven 设计的典范。

7.3 互补关系而非竞争关系

尽管三个项目都被贴上 "AI Agent" 标签, 但它们实际上几乎不竞争:

  • Hermes Agent vs OpenClaw: 直接竞争, 但 Hermes 提供 hermes claw migrate 让 OpenClaw 用户平滑迁移, 反映双方默认目标用户重叠。
  • Hermes Agent vs DeepSeek Harness: 互补. Hermes 是 Python 终端用户工具, DeepSeek 是 TypeScript 框架, 适合不同人群。
  • OpenClaw vs DeepSeek Harness: 互补. OpenClaw 面向终端用户, DeepSeek 面向 agent builder。

真正的事实: 三个项目是生态互补关系, 不是零和竞争。

7.4 各自的优势与适用场景

选择 Hermes Agent 的场景

  • 你需要 自学习能力 (skill 自动生成 / FTS5 session 搜索)
  • 你的部署是 云原生 (Vercel Sandbox / Modal / Daytona)
  • 你想在 任意 IM 与 agent 对话 (但 IM 数量比 OpenClaw 少)
  • 你信任 Nous Research 的商业服务

选择 OpenClaw 的场景

  • 你需要 个人设备主权 (永远在你机器上跑)
  • 你需要 20+ IM 通道 (包括 Feishu / WeChat / iMessage 等小众通道)
  • 你想参与 Foundation 治理 而非公司治理
  • 你需要 macOS / iOS / Android 原生应用
  • 你重视 本地优先 (Local-first) 哲学

选择 DeepSeek Harness 的场景

  • 你要 构建 agent 产品, 自己集成 harness
  • 你需要 多平台沙箱 (bwrap / Landlock / Seatbelt)
  • 你重视 Capability Seams 架构原则
  • 你想用 TypeScript / Node.js 构建 agent 系统
  • 你需要 可替换的 agent loop (dsh-agent-loop is swappable)

7.5 共同的下一步方向

三个项目都面临相似的挑战:

  1. 协议演化: MCP 已成为事实标准, A2A 正在崛起 (Google A2A)。三项目都在跟进。
  2. 可观测性: 需要更成熟的 tracing/eval/monitoring 生态 (Langfuse, Arize Phoenix)。
  3. Agent 安全: 工具调用的权限控制、命令注入防御 (三项目都有 sandbox, 但仍有提升空间)。
  4. 长上下文: 当 session 长度到 100K+ tokens 时的管理与检索。

    5. 7.6 一个观察：AI Agent 进入"分层生态"

    三个项目的并存揭示了一个重要趋势: AI Agent 不再是"一个万能框架", 而是进入分层生态:

    层代表项目角色
    终端用户层OpenClawPersonal AI Assistant
    开发者工具层Hermes AgentSelf-improving Coding Agent
    框架层DeepSeek HarnessPlugin Runtime / SDK
    底层模型层(各家 LLM)提供 brain

    这种分层让每个项目可以在自己的层做深, 而不必试图做"一切"。

    7.7 工业界与开源社区的影响

    • OpenClaw (39万★) 改变了"个人 AI 助手"的范式, 类似 Homebrew 对 macOS 包管理的革命。
    • DeepSeek Harness 为 agent 工程化树立了新的质量标准 (postmortem, capability seams, prose standard)。
    • Hermes Agent 探索了自学习 agent 的可能, 影响下一代 agent 设计。

    7.8 对中国 AI Agent 生态的启发

    三个项目的不同路径对中国 AI Agent 生态的启发:

    1. Hermes 模式: 自学习闭环 + 云原生部署, 适合中国 AI 公司做"差异化" (e.g. 蚂蚁 / 字节 / 腾讯的内部 agent)
    2. OpenClaw 模式: 本地主权 + IM 通道, 适合中国国情 (微信 / 飞书 / 钉钉) 的"个人助手"产品
    3. DeepSeek Harness 模式: 工业级 monorepo + capability seams, 适合中国大厂做基础设施级 agent runtime
