C.4KVM 验证清单 (Pre-flight)

部署前必须执行的检查清单 (脚本):

#!/bin/bash
# /opt/agent-platform/scripts/preflight.sh
# 部署前 KVM 验证

set -e
FAIL=0

echo "=== KVM 硬件支持 ==="
if grep -E "vmx|svm" /proc/cpuinfo > /dev/null; then
  echo "✓ CPU 支持硬件虚拟化"
else
  echo "✗ CPU 不支持 VT-x/AMD-V"; FAIL=1
fi

echo
echo "=== KVM 内核模块 ==="
for mod in kvm kvm_intel kvm_amd vhost_net vsock virtio_fs; do
  if lsmod | grep -q "^$mod"; then
    echo "✓ $mod 已加载"
  else
    echo "✗ $mod 未加载 (尝试: modprobe $mod)"
    FAIL=1
  fi
done

echo
echo "=== /dev/kvm 设备 ==="
if [ -e /dev/kvm ]; then
  if [ -r /dev/kvm ] && [ -w /dev/kvm ]; then
    echo "✓ /dev/kvm 可读写"
  else
    echo "✗ /dev/kvm 存在但无权限"; FAIL=1
  fi
else
  echo "✗ /dev/kvm 不存在"; FAIL=1
fi

echo
echo "=== cgroups v2 ==="
if mount | grep -q "cgroup2.* /sys/fs/cgroup"; then
  echo "✓ cgroups v2 已挂载"
else
  echo "✗ 未使用 cgroups v2 (内核启动参数需 systemd.unified_cgroup_hierarchy=1)"; FAIL=1
fi

echo
echo "=== Landlock 内核支持 ==="
if [ -e /sys/kernel/security/landlock ]; then
  echo "✓ Landlock 已启用"
else
  echo "⚠ Landlock 未启用 (Kernel >= 5.13 可启用 CONFIG_SECURITY_LANDLOCK=y)"; FAIL=1
fi

echo
echo "=== 系统资源 ==="
TOTAL_MEM=$(free -g | awk '/^Mem:/ {print $2}')
if [ "$TOTAL_MEM" -ge 8 ]; then
  echo "✓ 内存 $TOTAL_MEM GB (>= 8 GB)"
else
  echo "✗ 内存 $TOTAL_MEM GB (< 8 GB 不推荐)"; FAIL=1
fi

DISK_FREE=$(df -BG / | awk 'NR==2 {print $4}' | tr -d 'G')
if [ "$DISK_FREE" -ge 50 ]; then
  echo "✓ 根分区剩余 $DISK_FREE GB (>= 50 GB)"
else
  echo "✗ 根分区剩余 $DISK_FREE GB (< 50 GB)"; FAIL=1
fi

echo
if [ $FAIL -eq 0 ]; then
  echo "=== 所有检查通过,可以部署 ==="
  exit 0
else
  echo "=== 存在 $FAIL 个问题,请修复后重试 ==="
  exit 1
fi

# /opt/agent-platform/deploy/docker-compose.yml
version: "3.9"

x-logging: &default-logging
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"

services:
  postgres:
    image: postgres:16-alpine
    container_name: agent-platform-pg
    restart: unless-stopped
    user: "70:70"  # postgres UID
    environment:
      POSTGRES_DB: agent_platform
      POSTGRES_USER: agent_platform
      POSTGRES_PASSWORD: ${PG_PASSWORD}     # 从 .env 读

    command:
      - "postgres"
      - "-c"
      - "config_file=/etc/postgresql/postgresql.conf"
    ports: !reset []   # 不暴露
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U agent_platform"]
      interval: 10s
      timeout: 5s
      retries: 5

    deploy:
      resources:
        limits:
          cpus: "4"

      test: ["CMD", "redis-cli", "ping"]

C.7高可用 [v1.0]

C.7.1 单点故障分析

组件单点?影响v1.0 方案
S 端服务器整机是全平台停机K8s 多副本 + 反亲和
PostgreSQL是数据丢失风险Patroni + 流复制 + S3 WAL 归档
Redis是会话 / 速率限制失效Sentinel 哨兵 + 自动 failover
KVM 宿主机是该节点 VM 全停KubeVirt + VM live migration
Nginx是C 端无法访问Ingress 副本 + LB

C.7.2 v1.0 架构目标

3 副本 S 端 API + LBK8s Deployment
  • K8s Deployment 3 副本 + HPA (按 CPU 自动扩缩)
  • Ingress (Nginx / Envoy) 前置 LB
  • WebSocket sticky session (cookie affinity)
PG 主从 + PatroniHA
  • 1 主 2 从,同步流复制 (synchronous_commit = on)
  • Patroni 自动 failover, RPO < 5s
  • WAL 持续归档到 S3
VM 自动漂移KubeVirt
  • VM 调度到多个 KVM 宿主机
  • 节点失效时,VM 在 30s 内漂移到健康节点
  • 挂载点 (virtiofs) 跟随 VM 迁移
