D.1定价哲学

三条原则

  1. 自托管永久免费:核心代码 AGPL-3.0 公开,用户可自由部署在自己的服务器上,零软件费用。这与商业 Agent 平台 (E2B $0.05/session) 形成根本差异。
  2. 云端订阅制:不想自己运维的用户,可以订阅托管版。定价按"VM 小时数 + Token 用量"双维度,不收数据 egress 费 (与 AWS 差异)。
  3. 不卖数据:用户 LLM API keys 自带,平台不收 LLM 调用差价;用户上传的 runtime 不被平台二次分发。

价值锚点

  • 开发者友好:个人免费档够用 (1 VM + 5 GB 挂载),小团队 ¥99/月就能上 5 VM
  • 团队友好:Team 档 ¥299/月比一个全职 SRE 工程师 (¥15k/月) 便宜 50 倍
  • 企业友好:Enterprise 按合同,通常 ¥30k+/年起,含 SLA 99.9% + 私有部署

何时选自托管?

  • 月活 VM ≥ 30 (云端 Team 档已经 ¥299/月,自己买服务器更划算)
  • 数据敏感 (金融 / 医疗 / 政府),数据不能出客户机房
  • 需要深度定制 (改源码、接内部系统)
  • 已有 K8s 运维团队

何时选云端?

  • 月活 VM < 10,只是个人或小团队
  • 无 Linux 运维经验
  • 想 5 分钟跑起来
  • 需要弹性扩缩 (业务有潮汐)

D.6.2 平台不赚 Token 差价

用户 LLM API keys 自己管理,平台仅做 转发,不在中间收任何费用:

  • 用户在平台设置页填入自己的 OpenAI/Anthropic key
  • VM 内 Agent 通过 OPENAI_API_KEY 环境变量直接调 LLM
  • S 端不做任何缓存、加价、二次封装
  • 成本完全透明 — 跟用户直接调 LLM 一样

D.6.3 缓存与省钱 (v0.3)

v0.3 引入 prompt cache + response cache,可在用户授权下减少 LLM 调用:

  • Prompt 缓存:相同 prefix 的请求复用 KV cache,降本 30-50%
  • Response 缓存:相同输入直接返缓存,降本 100% (适用工具调用类)
  • 缓存策略:Redis + TTL,用户可关
  • 缓存节省的部分 100% 归用户,平台不抽成

D.6.4 ROI 案例

案例:5 人小团队 (¥8k/月)

原有流程:3 个开发者每天花 2 小时处理重复任务 (数据清洗 / 报表生成 / 文档改写),5 × 2 × 22 = 220 小时/月

使用本平台后:Agent 自动处理 70% 重复任务 = 154 小时/月节省

按 ¥150/小时 开发成本 = ¥23,100/月 价值

平台 + LLM 成本:¥99/月 (Pro) + ¥1,200/月 (LLM) = ¥1,299/月

ROI = 23,100 / 1,299 = 17.8 倍,一个月回本
