附录 A · API 契约

REST 完整路由 + WebSocket 消息协议 + gRPC 内部接口 + 错误码 + 速率限制。本附录是 v0.1 C/S 接口的契约定义,所有后端工程师与前端工程师以本附录为准;任何变更需更新本文档与 OpenAPI spec。

REST ~30 endpoints WebSocket 15 message types gRPC 6 services OpenAPI 3.1 Base URL https://api/{tenant}/v1

A.1通用约定

A.1.1 Base URL

  • 生产:https://api.agent-platform.example.com/v1
  • 自托管:https://{your-server}:8443/v1
  • WebSocket:wss://api/v1/ws

A.1.2 通用 Header

Header必填说明
Authorization: Bearer {jwt}是 (除登录外)access token
X-Request-ID否客户端生成的 UUID,用于追踪
X-Trace-Context否W3C traceparent
Content-Type: application/json是所有 POST/PATCH
Accept-Language否默认 zh-CN

A.7WebSocket 协议

A.7.1 连接

wss://api/v1/ws?vm_id=vm_abc123
Authorization: Bearer {jwt} (通过 query 也可, 浏览器友好)

→ 服务端 → 客户端
{"type":"hello","server_version":"0.1.0","ts":"..."}

← 客户端 → 服务端
{"type":"subscribe","topics":["events","stream"]}

A.7.2 完整消息类型

type方向用途频次
helloS→C连接建立1
subscribeC→S订阅 topic低
user_messageC→S发送用户消息 (REST 替代)低
tool_approvalC→S批准/拒绝工具调用中
pingC↔S心跳30s
pongS↔C心跳应答30s
vm_stateS→CVM 状态变化低
mount_stateS→C挂载状态变化低
stream_tokenS→CLLM 流式响应 token高 (50/s)
stream_doneS→C流式响应结束中
tool_callS→C工具调用开始中
tool_resultS→C工具调用结果中
file_changeS→C文件变更 (diff)中
vm_metricS→CCPU/MEM 等指标 (每 10s)低
errorS→C错误/异常低

A.7.3 关键消息 schema

// 流式 token
{"type":"stream_token","conv_id":"conv_xyz","seq":42,"delta":"你好"}

// 工具调用
{"type":"tool_call","call_id":"tc_001","name":"read_file","args":{"path":"/workspace/foo/main.py"},"ts":"..."}

// 工具结果
{"type":"tool_result","call_id":"tc_001","result":{"content":"...","size":4231},"duration_ms":87,"ts":"..."}

// 文件变更
{"type":"file_change","path":"/workspace/foo/main.py","diff":"@@ -10,3 +10,3 @@\n-old line\n+new line","ts":"..."}

// VM 指标
{"type":"vm_metric","cpu_pct":23.4,"mem_mb":412,"net_kbps":{"rx":12,"tx":8},"disk_mbps":{"r":2.1,"w":0.5},"ts":"..."}

A.7.4 客户端实现要点

  • 使用 WebSocket 原生 API + 自动重连 (exp backoff)
  • stream_token 累加 delta 到本地缓冲区,每 100ms 触发渲染
  • 心跳:30s 间隔发 ping, 5s 内未收 pong 视为断开
  • 断线恢复:连接成功后用 GET /conversations/{id}/messages?after_seq={last_seq} 拉取丢失的消息
  • 背压:服务端每秒推 60 条上限,超过则合并 delta

A.8.2 proto 示例 (VMManager)

// agent_platform.proto
syntax = "proto3";
package agent_platform.vm;

service VMManager {
  rpc Create(CreateRequest) returns (CreateResponse);
  rpc Start(StartRequest) returns (StartResponse);
  rpc Pause(PauseRequest) returns (PauseResponse);
  rpc Resume(ResumeRequest) returns (ResumeResponse);
  rpc Destroy(DestroyRequest) returns (DestroyResponse);
  rpc Get(GetRequest) returns (GetResponse);
  rpc Stream(StreamRequest) returns (stream VMEvent);  // 服务端推送
}

message CreateRequest {
  string owner_id = 1;
  string runtime_id = 2;
  string name = 3;
  Resources resources = 4;
  repeated Mount mounts = 5;
}

message Resources {
  uint32 vcpus = 1;
  uint32 memory_mb = 2;
  uint32 disk_gb = 3;
}

message Mount {
  string host_path = 1;
  string vm_path = 2;
  string mode = 3;        // "read-write" or "read-only"
  uint32 quota_mb = 4;
}

message CreateResponse {
  string vm_id = 1;
  string state = 2;
  int64 created_at = 3;
}

message VMEvent {
  string vm_id = 1;
  string event_type = 2;  // "state_change", "metric", "error"
  google.protobuf.Any payload = 3;
}

A.9.1 HTTP 错误码完整列表

HTTPcode触发场景C 端处理建议
400VALIDATION_ERROR字段缺失/格式错表单字段标红
400INVALID_EMAIL邮箱格式错输入框提示
401UNAUTHORIZEDJWT 无效/过期清空本地 token 跳登录
401TOKEN_EXPIREDaccess 过期静默用 refresh 重试一次
403FORBIDDEN无权限 (他人 VM 等)toast "无权访问"
403PATH_NOT_IN_WHITELIST挂载路径不在白名单toast + 引导用户改路径
404NOT_FOUNDVM/mount 不存在404 页或列表刷新
409PATH_CONFLICT挂载路径冲突toast + 高亮冲突项
409VM_STATE_INVALIDVM 状态不允许操作toast 当前状态 + 操作按钮禁用
409RUNTIME_IN_USERuntime 还在被 VM 用toast 提示先停 VM
422QUOTA_EXCEEDEDVM 配额超限弹窗引导升级
422MANIFEST_INVALID上传 Runtime 校验失败显示校验失败详情
422RUNTIME_BOOT_FAILED试启动失败显示启动日志

500INTERNALS 端崩溃toast + Sentry 上报
503VM_BOOT_FAILEDVM 启动失败显示日志 + 重试按钮
503PLATFORM_UNAVAILABLE整体不可用维护页
