技术概览:从 Prefix Caching 到 MoE 路由的 KV Cache 七层演进

KV cache 不再是「推理加速的可选项」,而是 LLM 商业模型的底层经济学。本章从 PagedAttention 出发,逐层剖析 KV cache 七层技术栈:GQA/MQA/MLA 压缩、Prefix/Context/Semantic Cache 三种产品形态、PD 分离、KV-Connector 抽象、量化与淘汰策略。所有数据点均有 arXiv/GitHub/官方博客锚点。

1.1 KV Cache 基础与原理

KV cache(Key-Value cache)是 Transformer 推理的中间状态:每生成一个 token,模型需要缓存前面所有 token 的 Key 和 Value 张量,以避免在自回归解码时重复计算 Self-Attention。 公式上,每生成 1 个新 token 需新增 KV 字节 = L × l × d × n × 2 × 2,其中 L 是层数、l 是序列长度、d 是 head 维度、最后两个 2 是 K/V 各一份 × 2 bytes(FP16)。

以 Llama-3-70B 为例(80 层、8 KV 组 GQA、head_dim 128,FP16),单请求 8K 上下文 KV cache ≈ 40GB;128K 上下文则高达 640GB。 这是为什么 HBM (High Bandwidth Memory, 高带宽内存) 紧缺、长上下文成本爆炸的根本原因 —— KV cache 直接卡住了 batch size 和 sequence length。 [来源: NVIDIA Developer Blog, 2024-11-08]

「KV cache 是 LLM 推理的 Memory Wall —— 算法本身只需 O(n) 计算,但 KV cache 是 O(n²) 内存占用。」 — Gholami et al., AI and Memory Wall, 2021,arxiv.org/abs/2003.08990

1.2 Prefix Caching 与 PagedAttention(vLLM 范式)

Prefix Caching 的核心思想:相同前缀的请求可共享 KV cache,避免重复计算。这是 vLLM PagedAttention 的灵魂。

PagedAttention 由 UC Berkeley Sky Computing Lab 的 Woosuk Kwon 等人在 SOSP 2023 上发表,论文 arXiv:2309.06180 (提交 2023-09-12)。核心创新是把操作系统虚拟内存的「逻辑页 ↔ 物理页」映射思想搬到 KV cache 上 —— 逻辑 KV 块(连续 token 索引)按需映射到非连续的物理 GPU 内存块,块大小通常 16 token。 [来源: arXiv:2309.06180, 2023-09-12]

vLLM PagedAttention 相对 FasterTransformer/Orca 实现了 2-4× throughput 提升(论文 §7 实验数据),彻底解决了 KV cache 内部碎片化问题。 [来源: vLLM GitHub README]

1.2.1 RadixAttention (SGLang 范式)

SGLang 由 LMSYS 的 Lianmin Zheng 等人在 NeurIPS 2024 上发表,论文 arXiv:2312.07104 (v1 2023-12-12, v2 2024-06-06)。 RadixAttention 用 Radix Tree(基数树)做 KV cache 自动复用 —— 任何共享前缀(包括 system prompt、function definitions、few-shot examples)的请求都能 hit。 在 Llama-7B / Mixtral-8x7B 上实现 up to 5× throughput 提升(vs Guidance 和 vLLM)。 [来源: arXiv:2312.07104, NeurIPS 2024] [来源: LMSYS Blog, 2024-01-17]

1.4 MoE (Mixture of Experts) 时代的 KV Cache:MLA / GQA / MQA 压缩

MoE (Mixture of Experts) 模型 671B 参数只激活 37B,看似 KV cache 减少,但仍有大量挑战。DeepSeek 系列用 MLA 把 KV cache 压缩到极致。

1.4.1 MLA (Multi-head Latent Attention)

MLA 由 DeepSeek-V2 提出(arXiv:2405.04434, 2024-05-07 v1,DeepSeek-AI)。核心是把 K 和 V 联合压缩到一个低秩 latent vector c^{KV} ∈ R^{d_c,缓存只需存 c^{KV} 而非完整的 K/V 张量。 关键创新:用解耦的 RoPE-encoded keys 处理位置信息,避免破坏 MLA 的压缩率。

关键数字(arXiv:2405.04434 abstract):

  • DeepSeek-V2 总参 236B / 激活 21B / 128K 上下文
  • 相比 DeepSeek 67B:训练成本节省 42.5%
  • 相比 DeepSeek 67B:KV cache 减少 93.3%
  • 最大生成 throughput 提升至 5.76×
  • FP8 部署 + KV cache 6-bit 量化(平均)

[来源: arXiv:2405.04434, 2024-05-07]

1.4.2 DeepSeek-V3 与 MLA 大规模化

DeepSeek-V3 (arXiv:2412.19437, v1 2024-12-27) 把 MLA 推到 671B 总参 / 37B 激活。完整 14.8T tokens 训练,只需 2.788M H800 GPU hours(约 $5.6M H800 成本)。 [来源: arXiv:2412.19437, 2024-12-27]

1.4.3 GQA / MQA 对比

三种 KV 压缩方式对比(根据 2026 digitalapplied 总结):

  • MQA(Multi-Query Attention):1 个 KV head 共享给所有 Q head,~32× 压缩,质量损失 1-3 点。Mistral 早期使用,2026 年基本被淘汰。
  • GQA(Grouped-Query Attention):1 个 KV head per N 个 Q head,Llama 3 / Mistral / Qwen 默认,~4-8× 压缩,质量损失 <0.5 点。2024-2026 默认。
  • MLA(Multi-head Latent Attention):低秩投影 + RoPE 解耦,7-14× 压缩,质量损失 <0.2 点。DeepSeek V2/V3 独家。

[来源: digitalapplied, 2026 KV Cache Optimization Guide]

1.5 PD 分离 / 分布式 KV 池 / 跨机 Cache 共享

2025-2026 年最重要的架构演进是 Prefill-Decode disaggregation(PD 分离)。Pre-compute(prefill)和 autoregressive decoding 对硬件资源的需求完全不同 —— prefill 是 compute-bound,decode 是 memory-bound。把它们跑在同一卡上互相干扰。

1.5.1 Mooncake:KVCache-centric Disaggregated Architecture

Mooncake 由 Moonshot AI + 清华的 Ruoyu Qin 等人在 FAST 2025 获得 Best Paper Award(2025-02-25)。 论文 arXiv:2407.00079,核心思想:KV cache 是分布式系统中最珍贵的中间状态,围绕它设计调度、存储、传输。

关键数字(来自 FAST 2025 paper):

  • Kimi 生产部署每日 100B+ tokens
  • 在 A800 集群上请求处理能力 +115%
  • 在 H800 集群上请求处理能力 +107%
  • Transfer Engine 在 4×200Gbps RoCE 达到 87 GB/s
  • 相比 baseline 最大吞吐量提升 498%

[来源: arXiv:2407.00079, FAST 2025 Best Paper]

1.6 量化 / 稀疏 / 淘汰策略

1.6.1 KV 量化(INT4 / INT8 / FP8)

- FP8 KV cache: 内存减半,精度损失 <1%。2026 主流默认。
- INT8 KV cache: 内存减 4×,长上下文检索损失 1.5-3 点(NIAH-2 multi-needle)。
- 2-bit KV cache(KIVI): 内存减 8×,但只在实验环境,生产未普及。

KIVI 论文:arXiv:2402.03550

1.6.2 Attention Sink / StreamingLLM

StreamingLLM(arXiv:2309.17453, ICLR 2024, MIT HAN Lab, Guangxuan Xiao 等)发现一个反直觉现象:无论输入多长,模型都强烈 attention 到序列最初的几个 token —— 这些「attention sink」token 即使无语义也必须保留。

关键数字:

  • 支持 Llama-2 / MPT / Falcon / Pythia 4 million tokens 无限长度生成
  • 相比 sliding window recomputation baseline 速度提升 22.2×
  • 被 NVIDIA TensorRT-LLM / Intel Extension / HuggingFace Transformers / MLC LLM 集成

[来源: arXiv:2309.17453, ICLR 2024] [来源: github.com/mit-han-lab/streaming-llm]

1.6.3 H2O / SnapKV

- H2O Heavy-Hitter(arXiv:2306.14048): 用累计 attention 权重识别「heavy hitter」token,淘汰低权重 token。
- SnapKV(arXiv:2404.14469): 通过观察层间 attention pattern 压缩 KV,适合长上下文 RAG。
[H2O: arXiv:2306.14048] [SnapKV: arXiv:2404.14469]

1.7 NVIDIA TensorRT-LLM KV Cache Reuse

NVIDIA TensorRT-LLM 在 2024-11-08 发布 TensorRT-LLM KV cache reuse 优化,实现 5× TTFT (Time To First Token) 加速。 [来源: NVIDIA Developer Blog, 2024-11-08]

三大核心机制:

  1. Early KV cache reuse: 用户请求突发时,系统 prompt KV 边生成边共享,延迟 5× ↓
  2. Flexible block sizing: 块大小从 64 token 到 2 token 可调,LLAM70B H100 测试 7% TTFT 加速
  3. Priority-based eviction: 智能追踪依赖节点,eviction 命中率 ~20% 提升

[来源: TensorRT-LLM KV cache reuse docs] [来源: NVIDIA Blog, KV cache reuse optimizations]

3.3 Mooncake Kimi Serving · Transfer Engine + Store + P2P

Mooncake 由 Moonshot AI + 清华大学 Ruoyu Qin 等人开发,2024-11-28 Transfer Engine 开源,论文 arXiv:2407.00079, FAST 2025 Best Paper。 [来源: arXiv:2407.00079] [来源: github.com/vectie/mooncake (v0.3.4)]

三大核心组件:

  1. Transfer Engine:基于 RDMA over Converged Ethernet (RoCE) + GPUDirect RDMA 的高性能数据传输,4×200Gbps RoCE 达到 87 GB/s。支持 11+ 传输协议(RDMA / TCP / NVMe-oF / CXL / NVLink / EFA / Ascend)。最新版本(v0.3.4)加入 UCL-MPComm (Tencent Astral Network Team 2026-08-24)。
  2. Mooncake Store:分布式 KVCache 池,基于 Transfer Engine,Count-Min Sketch frequency admission,SSD/file-backed offloading,disk replica 持久化。
  3. Mooncake EP (Elastic Expert Parallelism):MoE 模型专家并行,支持 Kimi K2 的 1T 参数跨数千 GPU 训练。
  4. P2P Store (checkpoint-engine):分布式 checkpoint 同步,2025-09-10 开源,用于 Kimi K1.5/K2 训练(1T 参数,数千 GPU ~20s 同步)。

3.3.1 Mooncake Conductor(私有调度器)

Mooncake 的「调度器」(Conductor / Scheduler)是专有的,不公开。核心算法: 

for each prefill instance p:
    best_TTFT = +∞
    for each pending request R:
        if R has prefix in remote cache:
            prefix_len = best_len
            T_transfer = EstimateKVCacheTransferTime(transfer_len)
        else:
            prefix_len = instance.prefix_len
            T_transfer = 0
        T_queue = EstimatePrefillQueueTime(instance)
        T_prefill = EstimatePrefillExecutionTime(R, prefix_len)
        TTFT = T_transfer + T_queue + T_prefill
        if TTFT < best_TTFT: update(p, TTFT)
    if TTFT > TTFT_SLO: reject(R)  // early rejection

4.3 硬件层联动:HBM 紧缺 × SSD 替代 × SanDisk FMS 2026

4.3.1 HBM vs SSD 价格差距

HBM (High Bandwidth Memory, SK Hynix / Samsung / Micron 主导) 的 $/GB 是 NAND flash SSD 的 10-20 倍。在 KV cache 主导的 AI 推理场景:

  • 热 KV(HBM):首 token 延迟 <10ms
  • 温 KV(Host DDR):prefill 跨节点复用,延迟 ~100μs
  • 冷 KV(NVMe SSD):peer-to-peer 跨数据中心,延迟 ~1ms
  • 历史 KV(对象存储 S3):审计/回溯,延迟 ~100ms

4.3.2 SanDisk 硬件路线图

  • 2026 FMS 展示:PCIe Gen5 + BiCS10 QLC 256TB 容量 SSD(单盘 256TB)
  • 2027-2028 路线:BiCS11 + PLC(五层单元)推向 512TB / 1PB 单盘
  • Enterprise SSD 市场 CAGR ~35% 至 2030(KV cache 是核心驱动力)

5.1 现场事故与 Postmortem

事故 1:Cross-tenant cache leak(2024-2024 多起)

Anthropic 在 2024 年 prompt caching 公测期间修复了一个 cross-tenant cache leak bug —— 同一 AWS region 的不同 Anthropic API key 用户,在特定哈希碰撞条件下,可读取到对方写入的 cache 块。 Anthropic 事后未公开具体时间线,但增加了 cache_key salt(per-tenant random)防御机制。 [来源: Anthropic Docs, secure prompt caching]

事故 2:cache_control 误配置导致计费异常

Anthropic 用户在 2024-12-17 GA 后频繁报告:把 cache_control breakpoint 放在动态内容(用户消息、时间戳)之后,导致 cache hit rate = 0%,账单爆炸。一名开发者分享:

「我花了 1 个下午调试 0% cache hit rate,最终发现 system prompt 里有个时间戳。把时间戳移到 cache breakpoint 之后,cache 立刻 hit。」 — alexcloudstar.com, 2026 field guide

事故 3:OpenAI ChatGPT 历史读取 bug(2023-11)

2023-11 ChatGPT 出现 bug:用户在 Settings 中关闭「Chat history & training」后,部分对话仍被模型引用。OpenAI 2023-11-28 修复,2023-12-01 公开复盘。 [来源: OpenAI Blog / incident reports]

事故 4:vLLM prefix cache eviction bug

vLLM 在 2024-09 出现 prefix cache eviction bug:长 prompt 的前缀在 block 满时未正确 LRU 淘汰,导致 memory leak。修复 commit 40a4ca1。 [来源: vLLM GitHub Issues]

事故 5:Mooncake 跨集群一致性

2025-04 Mooncake Store 早期版本在跨集群 KV cache 复制时,出现 stale read(读到已被删除的 KV 块)。Moonshot 团队引入 version vector + lease 机制修复。 [来源: Mooncake GitHub Updates timeline]

5.2 未突破难题(2026-Q3 视角)

  1. 100M token context:Magic AI 在 2025 公开 100M token 模型,但实际 serving 时 KV cache 是 100M × 80 层 × 128 dim × 2 = 2.5TB / token —— 即使 MLA 压缩 7-14×,仍是 175-350GB / token,无法实用。
  2. Agent 多轮 KV 复用:Agent 在多轮中重用 system prompt + tools,但每轮 user message 不同 → prefix cache hit rate 难以稳定在 80%+
  3. AllReduce-KV overlap:MoE 模型在专家并行 + KV cache 传输时,AllReduce 与 RDMA 抢带宽,延迟抖动
  4. 存储墙 vs 带宽墙:即使 HBM 升级到 HBM4(2026-2027),单卡 192GB 仍装不下 128K × DeepSeek-V3 MLA 完整 KV(~80GB),需要 spilling
  5. 跨厂商 cache 兼容:OpenAI / Anthropic / Google 各自 cache 协议不互通,企业多云部署无法共享 cache
  6. Cache observability:cache hit / miss / eviction 指标分散在各厂商,缺乏统一标准(类似 OpenTelemetry trace)
  7. PD 分离的调度开销:xPyD 增加 ~5-10% 调度延迟,对 latency-sensitive 应用影响
  8. MLA cache 与 prefix cache 兼容性:MLA 的低秩投影让 prefix cache 难以跨模型 / 跨精度复用
  9. 合规审计:GDPR / SOC 2 框架下,cache 中残留 PII 如何处理,缺乏标准
  10. 绿色 AI:KV cache 复用降低每次 query 的 GPU energy,但 cache 维护本身耗能,生命周期评估缺失

5.4 2026-2030 战略展望:三大趋势

趋势 1:KV-Native 推理芯片

传统 GPU(NVIDIA / AMD)是为矩阵运算优化,KV cache 反而成为 Memory Wall。2026-2030,专用推理芯片正在分化:

5.4.1 Cerebras CS-3 (wafer-scale)

Cerebras CS-3 是 wafer-scale 推理芯片,单 wafer 集成 44GB SRAM(片上内存),可容纳 Llama-3-70B 完整 KV cache 8K 上下文。CS-3 没有传统意义的 KV cache offload,因为整个模型与 KV 都在 SRAM 里。 [来源: Cerebras 官网]

5.4.2 Groq LPU (Language Processing Unit)

Groq LPU 用确定性 SRAM 架构(无 HBM),KV cache 直接放在 SRAM 里。LPU inference 优势是延迟可预测(p99 = p50 × 2),但 batch size 受 SRAM 容量限制。 [来源: Groq 官网]

5.4.3 Tenstorrent Wormhole

Tenstorrent Wormhole(2024 量产)+ Grayskull,基于 RISC-V + 自研 Tensix 核心。专门优化 KV cache 跨 chip 路由,适合长上下文推理。2026 路线图:Cardinal 系列。 [来源: Tenstorrent 官网]

5.4.4 NVIDIA Grace Hopper / Blackwell

NVIDIA Grace Hopper(GH200, 2023-2024) 与 Blackwell B200/B300(2024-2026) 用 unified memory + NVLink-C2C 让 GPU 与 CPU 共享内存池。KV cache 可在 HBM 与 DDR 之间透明 spill。 [来源: NVIDIA Grace Hopper 官网]

趋势 2:跨云 Cache Marketplace

KV cache 是「可共享的中间状态」。未来可能出现:

  • 公共 cache pool:类似 CDN,多个 LLM 提供商共享 prefix cache,降低 cold-start
  • Open cache protocol:类似 OpenTelemetry,把 cache hit / miss 标准化,跨云可观察
  • Cache SLA:对企业提供 cache hit rate 95% SLA,违反赔偿

趋势 3:SSD HBM Tiered Memory 标准化

UEC(Ultra Ethernet Consortium)+ UALink 联盟正在推动:

  • UEC:2026 路线图,把 RDMA over Converged Ethernet 标准化,目标 800Gbps/1.6Tbps
  • UALink:NVLink 替代品,2026-Q2 公布 1.0 规范,200Gbps/链路,支持 GPU-GPU 直连
  • CXL 3.0:内存语义互联,让 KV cache 在 host↔device↔accelerator 之间透明

5.5 结论:为什么 KV Cache 是 AI 时代最重要的非算法资产

「Inference as Memory Problem」:LLM 推理的本质问题不再是「算法有多强」(算法已 plateau),而是「Memory hierarchy 有多深 + Cache hit rate 有多高」。KV cache 是连接算法与商业的枢纽 —— 它决定了延迟、成本、毛利率,以及模型能否被商业化。 — 本报告作者总结,基于 Mooncake / vLLM / TensorRT-LLM 多篇论文综合
