产品技术深度:vLLM / SGLang / Mooncake / LMCache 全栈拆解

八大开源项目构成了 KV cache 推理的工程栈:vLLM (PagedAttention 起家)、SGLang (RadixAttention + HiCache)、Mooncake (Transfer Engine 分布式)、LMCache (cache-centric serving)、LMDeploy (InternLM 出品)、TensorRT-LLM (NVIDIA)、LightLLM、FlashInfer。本章逐个拆解核心架构与最新演进。

3.1 vLLM · PagedAttention 路线与 KV-Connector 抽象

vLLM 由 UC Berkeley Sky Computing Lab 的 Woosuk Kwon 等人发起,2023 年开源。原始论文 arXiv:2309.06180, SOSP 2023,标题《Efficient Memory Management for Large Language Model Serving with PagedAttention》。 [来源: vLLM GitHub]

核心架构演进:

  1. v0.1 - v0.3 (2023-2024):PagedAttention 落地,block size 16 token,实现 2-4× throughput 提升
  2. v0.4 - v0.5 (2024):Prefix caching 1.0,连续批处理优化,异步输出
  3. v0.6 (2024-Q4):Speculative decoding,Chunked prefill,MoE 支持
  4. v0.7 (2025-Q1):Multi-LoRA,Tool calling
  5. v1.0 (2025-01-27):KV-Connector API 抽象,把 KV cache 传输从内部实现变成可插拔 backend;xPyD (Prefill/Decode disaggregation) 集成 Mooncake Transfer Engine

KV-Connector 抽象(v1 引入)是 vLLM 最重要的架构决策:它让 KV cache 复用从「单实例内部」变成「跨实例 / 跨机 / 跨数据中心」。Mooncake Transfer Engine 在 2025-12-19 集成进 vLLM v1,作为 default remote KV-Connector backend。 [来源: vLLM v1 docs]

3.1.1 vLLM Ascend NPU 后端

vLLM-Ascend(docs.vllm.ai/projects/ascend)是 vLLM 在华为昇腾 NPU 上的官方后端,2025-08-18 集成 Mooncake Transfer Engine,支持在 NPU 集群上做 PD 分离 + KV cache 跨机共享。

3.2 SGLang · RadixAttention + HiCache 三级存储 + EPD

SGLang(github.com/sgl-project/sglang)由 Stanford LMSYS 的 Lianmin Zheng 等人发起。原始论文 arXiv:2312.07104, NeurIPS 2024,2024-01-17 LMSYS Blog 发布。 [来源: LMSYS Blog, SGLang with RadixAttention]

核心特性:

  • RadixAttention:Radix Tree 自动前缀匹配,LRU eviction,eviction 递归叶节点。在 Llama-7B / Mixtral-8x7B 上 up to 5× throughput
  • HiCache(2025-09-10):三级存储 Device/Host/Remote,扩展 RadixAttention 到多层缓存
  • EPD(Encode-Prefill-Decode, 2025-12-23 / 2026-01-12 blog):多模态分离,处理视觉 token 时与文本 prefill/decode 解耦
  • Large-scale EP(2025-05-05):DeepSeek 96 H100 PD 分离部署指南
  • Kimi K2 部署(2025-07-20):128 H200 GPU,224k prefill / 288k decode tokens/s

3.2.1 SGLang 与 Mooncake 集成时间线

  • 2025-04-10:Mooncake Transfer Engine 集成
  • 2025-05-05:DeepSeek PD 分离 96 H100 部署指南
  • 2025-07-20:Kimi K2 128 H200 PD 分离 + 大规模 EP
  • 2025-09-10:HiCache 三级存储(Device/Host/Remote),作为 Mooncake Store 的 hierarchical backend

3.3 Mooncake Kimi Serving · Transfer Engine + Store + P2P

Mooncake 由 Moonshot AI + 清华大学 Ruoyu Qin 等人开发,2024-11-28 Transfer Engine 开源,论文 arXiv:2407.00079, FAST 2025 Best Paper。 [来源: arXiv:2407.00079] [来源: github.com/vectie/mooncake (v0.3.4)]

三大核心组件:

  1. Transfer Engine:基于 RDMA over Converged Ethernet (RoCE) + GPUDirect RDMA 的高性能数据传输,4×200Gbps RoCE 达到 87 GB/s。支持 11+ 传输协议(RDMA / TCP / NVMe-oF / CXL / NVLink / EFA / Ascend)。最新版本(v0.3.4)加入 UCL-MPComm (Tencent Astral Network Team 2026-08-24)。
  2. Mooncake Store:分布式 KVCache 池,基于 Transfer Engine,Count-Min Sketch frequency admission,SSD/file-backed offloading,disk replica 持久化。
  3. Mooncake EP (Elastic Expert Parallelism):MoE 模型专家并行,支持 Kimi K2 的 1T 参数跨数千 GPU 训练。
  4. P2P Store (checkpoint-engine):分布式 checkpoint 同步,2025-09-10 开源,用于 Kimi K1.5/K2 训练(1T 参数,数千 GPU ~20s 同步)。

3.3.1 Mooncake Conductor(私有调度器)

Mooncake 的「调度器」(Conductor / Scheduler)是专有的,不公开。核心算法: 

for each prefill instance p:
    best_TTFT = +∞
    for each pending request R:
        if R has prefix in remote cache:
            prefix_len = best_len
            T_transfer = EstimateKVCacheTransferTime(transfer_len)
        else:
            prefix_len = instance.prefix_len
            T_transfer = 0
        T_queue = EstimatePrefillQueueTime(instance)
        T_prefill = EstimatePrefillExecutionTime(R, prefix_len)
        TTFT = T_transfer + T_queue + T_prefill
        if TTFT < best_TTFT: update(p, TTFT)
    if TTFT > TTFT_SLO: reject(R)  // early rejection

3.3.2 Mooncake PyTorch Ecosystem 成员

2026-02 加入 PyTorch Ecosystem,标志其从「Moonshot 自家平台」升级为「PyTorch 核心基础设施」。TorchSpec 使用 Mooncake 解耦推理与训练的 speculative decoding。

3.4 LMCache × Mooncake · Cache-Centric Serving

LMCache(github.com/LMCache/LMCache)是 UC Berkeley Sky Lab 出品的 cache-centric serving 库,与 vLLM 深度集成。

3.4.1 LMCache 核心机制

LMCache 把 KV cache 视为「分布式系统中的第一公民」:

  • LMCache remote connector:把 KV cache 存到 GPU↔CPU↔SSD↔NVMe 多层
  • PD-disagg 共享:Prefill 实例把 KV 推给 Decode 实例,跨机跨节点复用
  • 2025-04-22:LMCache 官方支持 Mooncake Store 作为 remote connector [来源: LMCache Blog, Tencent integration]
  • 2025-05-08:LMCache × Mooncake 联合宣布 cache-centric serving

3.5 NVIDIA TensorRT-LLM · Inflight Batching + KV cache Reuse

TensorRT-LLM(github.com/NVIDIA/TensorRT-LLM)是 NVIDIA 官方的高性能 LLM 推理引擎,在 Hopper / Blackwell GPU 上深度优化。

KV cache 核心特性:

  1. Inflight-batching scheduler:动态 batch 调整,保证 GPU 持续利用
  2. KV cache reuse(2024-11-08):Early reuse + Flexible block + Priority eviction,5× TTFT 加速
  3. Multi-GPU Multi-Node:Tensor Parallelism + Pipeline Parallelism + Expert Parallelism
  4. Speculative decoding:Medusa / Eagle / Draft model 多策略
  5. KV cache event API:Block store / remove / update 事件广播,支持 KV-aware routing
  6. Host memory offload:Grace-Hopper 架构下把冷 block 卸载到 CPU 内存

[来源: TensorRT-LLM KV cache reuse docs]

3.6 LMDeploy · InternLM 出品

LMDeploy(github.com/InternLM/lmdeploy)由上海 AI Lab / InternLM 团队出品,2025-06-20 成为 Mooncake PD 分离的官方 backend 之一。专注于 TurboMind 引擎 + 高吞吐量化部署。

3.7 LightLLM · ModelTC 出品

LightLLM(github.com/ModelTC/lightllm)是早期 vLLM 替代方案之一,使用 async + token-wise 调度。2025-2026 仍在活跃维护,但社区影响力下降。

3.8 FlashInfer · 高性能 Attention Kernel

FlashInfer(github.com/flashinfer-ai/flashinfer)是 UCSD / CMU 的高性能 attention / GEMM kernel 库。SGLang、vLLM、TensorRT-LLM 都集成了它的 kernel。StreamingLLM / KIVI 等压缩算法通常与 FlashInfer kernel 配合使用。

3.9 xLLM · 京东出品

xLLM(github.com/jd-opensource/xllm)是京东 2026 高性能推理引擎,2025-08-23 集成 Mooncake,做混合 KV cache 全局管理 + 智能 offload + prefetch。

3.10 NIXL · NVIDIA Inference Transfer Library

NIXL(github.com/ai-dynamo/nixl)是 NVIDIA Dynamo 项目的 transfer library,2025-05-09 官方支持 Mooncake Transfer Engine 作为 backend plugin,补齐 NVIDIA 生态与 Moonshot 生态的桥梁。
