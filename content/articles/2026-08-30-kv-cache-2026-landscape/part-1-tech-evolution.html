技术概览:从 Prefix Caching 到 MoE 路由的 KV Cache 七层演进

KV cache 不再是「推理加速的可选项」,而是 LLM 商业模型的底层经济学。本章从 PagedAttention 出发,逐层剖析 KV cache 七层技术栈:GQA/MQA/MLA 压缩、Prefix/Context/Semantic Cache 三种产品形态、PD 分离、KV-Connector 抽象、量化与淘汰策略。所有数据点均有 arXiv/GitHub/官方博客锚点。

1.1 KV Cache 基础与原理

KV cache(Key-Value cache)是 Transformer 推理的中间状态:每生成一个 token,模型需要缓存前面所有 token 的 Key 和 Value 张量,以避免在自回归解码时重复计算 Self-Attention。 公式上,每生成 1 个新 token 需新增 KV 字节 = L × l × d × n × 2 × 2,其中 L 是层数、l 是序列长度、d 是 head 维度、最后两个 2 是 K/V 各一份 × 2 bytes(FP16)。

以 Llama-3-70B 为例(80 层、8 KV 组 GQA、head_dim 128,FP16),单请求 8K 上下文 KV cache ≈ 40GB;128K 上下文则高达 640GB。 HBM (High Bandwidth Memory, 高带宽内存) 紧缺、长上下文成本爆炸的根本原因 —— KV cache 直接卡住了 batch size 和 sequence length。 [来源: NVIDIA Developer Blog, 2024-11-08]

「KV cache 是 LLM 推理的 Memory Wall —— 算法本身只需 O(n) 计算,但 KV cache 是 O(n²) 内存占用。」 — Gholami et al., AI and Memory Wall, 2021,arxiv.org/abs/2003.08990

1.2 Prefix Caching 与 PagedAttention(vLLM 范式)

Prefix Caching 的核心思想:相同前缀的请求可共享 KV cache,避免重复计算。这是 vLLM PagedAttention 的灵魂。

PagedAttention 由 UC Berkeley Sky Computing Lab 的 Woosuk Kwon 等人在 SOSP 2023 上发表,论文 arXiv:2309.06180 (提交 2023-09-12)。核心创新是把操作系统虚拟内存的「逻辑页 ↔ 物理页」映射思想搬到 KV cache 上 —— 逻辑 KV 块(连续 token 索引)按需映射到非连续的物理 GPU 内存块,块大小通常 16 token。 [来源: arXiv:2309.06180, 2023-09-12]

vLLM PagedAttention 相对 FasterTransformer/Orca 实现了 2-4× throughput 提升(论文 §7 实验数据),彻底解决了 KV cache 内部碎片化问题。 [来源: vLLM GitHub README]

1.2.1 RadixAttention (SGLang 范式)

SGLang 由 LMSYS 的 Lianmin Zheng 等人在 NeurIPS 2024 上发表,论文 arXiv:2312.07104 (v1 2023-12-12, v2 2024-06-06)。 RadixAttention 用 Radix Tree(基数树)做 KV cache 自动复用 —— 任何共享前缀(包括 system prompt、function definitions、few-shot examples)的请求都能 hit。 在 Llama-7B / Mixtral-8x7B 上实现 up to 5× throughput 提升(vs Guidance 和 vLLM)。 [来源: arXiv:2312.07104, NeurIPS 2024] [来源: LMSYS Blog, 2024-01-17]

1.4 MoE (Mixture of Experts) 时代的 KV Cache:MLA / GQA / MQA 压缩

MoE (Mixture of Experts) 模型 671B 参数只激活 37B,看似 KV cache 减少,但仍有大量挑战。DeepSeek 系列用 MLA 把 KV cache 压缩到极致。

1.4.1 MLA (Multi-head Latent Attention)

MLA 由 DeepSeek-V2 提出(arXiv:2405.04434, 2024-05-07 v1,DeepSeek-AI)。核心是把 K 和 V 联合压缩到一个低秩 latent vector c^{KV} ∈ R^{d_c},缓存只需存 c^{KV} 而非完整的 K/V 张量。 关键创新:用解耦的 RoPE-encoded keys 处理位置信息,避免破坏 MLA 的压缩率。

关键数字(arXiv:2405.04434 abstract):

  • DeepSeek-V2 总参 236B / 激活 21B / 128K 上下文
  • 相比 DeepSeek 67B:训练成本节省 42.5%
  • 相比 DeepSeek 67B:KV cache 减少 93.3%
  • 最大生成 throughput 提升至 5.76×
  • FP8 部署 + KV cache 6-bit 量化(平均)

[来源: arXiv:2405.04434, 2024-05-07]

1.4.2 DeepSeek-V3 与 MLA 大规模化

DeepSeek-V3 (arXiv:2412.19437, v1 2024-12-27) 把 MLA 推到 671B 总参 / 37B 激活。完整 14.8T tokens 训练,只需 2.788M H800 GPU hours(约 $5.6M H800 成本)。 [来源: arXiv:2412.19437, 2024-12-27]

1.4.3 GQA / MQA 对比

三种 KV 压缩方式对比(根据 2026 digitalapplied 总结):

  • MQA(Multi-Query Attention):1 个 KV head 共享给所有 Q head,~32× 压缩,质量损失 1-3 点。Mistral 早期使用,2026 年基本被淘汰。
  • GQA(Grouped-Query Attention):1 个 KV head per N 个 Q head,Llama 3 / Mistral / Qwen 默认,~4-8× 压缩,质量损失 <0.5 点。2024-2026 默认。
  • MLA(Multi-head Latent Attention):低秩投影 + RoPE 解耦,7-14× 压缩,质量损失 <0.2 点。DeepSeek V2/V3 独家。

[来源: digitalapplied, 2026 KV Cache Optimization Guide]

1.5 PD 分离 / 分布式 KV 池 / 跨机 Cache 共享

2025-2026 年最重要的架构演进是 Prefill-Decode disaggregation(PD 分离)。Pre-compute(prefill)和 autoregressive decoding 对硬件资源的需求完全不同 —— prefill 是 compute-bound,decode 是 memory-bound。把它们跑在同一卡上互相干扰。

1.5.1 Mooncake:KVCache-centric Disaggregated Architecture

Mooncake 由 Moonshot AI + 清华的 Ruoyu Qin 等人在 FAST 2025 获得 Best Paper Award(2025-02-25)。 论文 arXiv:2407.00079,核心思想:KV cache 是分布式系统中最珍贵的中间状态,围绕它设计调度、存储、传输。

关键数字(来自 FAST 2025 paper):

  • Kimi 生产部署每日 100B+ tokens
  • 在 A800 集群上请求处理能力 +115%
  • 在 H800 集群上请求处理能力 +107%
  • Transfer Engine 在 4×200Gbps RoCE 达到 87 GB/s
  • 相比 baseline 最大吞吐量提升 498%

[来源: arXiv:2407.00079, FAST 2025 Best Paper]

vLLM 在 v1 中引入 KV-Connector 抽象,把 KV cache 传输从内部实现变成可插拔 backend。Mooncake Store 作为 KV-Connector backend 在 2025-12-19 集成进 vLLM v1,支持 xPyD (Prefill/Decode disaggregation)。 [来源: vLLM Docs]

1.6 量化 / 稀疏 / 淘汰策略

1.6.1 KV 量化(INT4 / INT8 / FP8)

- FP8 KV cache: 内存减半,精度损失 <1%。2026 主流默认。
- INT8 KV cache: 内存减 4×,长上下文检索损失 1.5-3 点(NIAH-2 multi-needle)。
- 2-bit KV cache(KIVI): 内存减 8×,但只在实验环境,生产未普及。

KIVI 论文:arXiv:2402.03550

1.6.2 Attention Sink / StreamingLLM

StreamingLLM(arXiv:2309.17453, ICLR 2024, MIT HAN Lab, Guangxuan Xiao 等)发现一个反直觉现象:无论输入多长,模型都强烈 attention 到序列最初的几个 token —— 这些「attention sink」token 即使无语义也必须保留。

关键数字:

  • 支持 Llama-2 / MPT / Falcon / Pythia 4 million tokens 无限长度生成
  • 相比 sliding window recomputation baseline 速度提升 22.2×
  • 被 NVIDIA TensorRT-LLM / Intel Extension / HuggingFace Transformers / MLC LLM 集成

[来源: arXiv:2309.17453, ICLR 2024] [来源: github.com/mit-han-lab/streaming-llm]

1.6.3 H2O / SnapKV

- H2O Heavy-Hitter(arXiv:2306.14048): 用累计 attention 权重识别「heavy hitter」token,淘汰低权重 token。
- SnapKV(arXiv:2404.14469): 通过观察层间 attention pattern 压缩 KV,适合长上下文 RAG。
[H2O: arXiv:2306.14048] [SnapKV: arXiv:2404.14469]

1.7 NVIDIA TensorRT-LLM KV Cache Reuse

NVIDIA TensorRT-LLM 在 2024-11-08 发布 TensorRT-LLM KV cache reuse 优化,实现 5× TTFT (Time To First Token) 加速。 [来源: NVIDIA Developer Blog, 2024-11-08]

三大核心机制:

  1. Early KV cache reuse: 用户请求突发时,系统 prompt KV 边生成边共享,延迟 5× ↓
  2. Flexible block sizing: 块大小从 64 token 到 2 token 可调,LLAM70B H100 测试 7% TTFT 加速
  3. Priority-based eviction: 智能追踪依赖节点,eviction 命中率 ~20% 提升

[来源: TensorRT-LLM KV cache reuse docs] [来源: NVIDIA Blog, KV cache reuse optimizations]
