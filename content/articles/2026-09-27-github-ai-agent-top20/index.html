CH.01研究方法与评选口径

1.1 分析对象：什么是"Agent 工程"

本报告的分析物种是 AI Agent 运行时/脚手架（harness）与框架工程——即给定 LLM，负责"循环驱动、工具调用、沙箱执行、记忆管理、子代理编排"的那层代码。用户给定的参照系（OpenHands / opencode / DeepSeek Harness 等）精确落在这一层。按此口径，候选项目分为四个范式：

范式定义代表

B · Agent 框架与 SDK供开发者编排 agent 的库：图/角色/工具抽象，自带运行时autogen、crewAI、agno、agentscope

D · 生态协议层agent 与工具世界之间的协议骨架（非运行时，但决定 harness 形态）modelcontextprotocol/servers

CH.03架构共性：Agent 通用执行循环

把 14 个深拆仓的代码摊开看，无论终端 CLI、浏览器自主体还是多智能体平台，骨架都是同一个有状态循环——感知（组装上下文）→ 推理（LLM）→ 行动（工具调用）→ 观察（结果回灌），外加一道权限闸门与一套终止判定。各项目的差异不在这个骨架，而在五个战术选择：① 上下文如何组装与压缩；② 动作的表达方式（function call / 编辑块 / 代码即动作）；③ 沙箱与权限的默认姿态；④ 记忆的持久化策略；⑤ 子代理的编排模型。

CH.04范式 A · CLI/IDE 编程 Agent：harness 物种的主干

榜内 10 席、合计超 125 万星——A 范式是 agent 工程的主干物种。本章深拆 9 仓（OpenClaw、opencode、codex、gemini-cli、cline、OpenHands、goose、aider、openinterpreter），画像 2 仓（continue、crush）。深拆揭示的最大真相是：它们的循环几乎相同，胜负全在四个"非循环"工程层——权限闸门、上下文治理、编辑表达、分发形态。

4.1 openclaw/openclaw @ 030a6ec：391k★ 断层榜首——个人 agent harness 的完全体

前身 Clawdbot 的 OpenClaw 是本榜第一（391k★，shields 实采），也是用户点名的参照系。它的答案与所有 CLI 同行不同：harness 的宿主不是终端，而是你的全部消息渠道与自有设备。架构是"网关+内核+渠道插件+节点"四层：

  • Agent loop：runAgentLoop（packages/agent-core/src/agent-loop.ts:68，改编自 pi-mono）——steering 回灌（:191）→ 流式采样（:252）→ 流内/收尾 tool_use 执行（:259/:292）→ toolResults 回灌（:327）→ hasMoreToolCalls 判定续轮（:317）。教科书式的 tool-use 循环，与 codex/opencode 同构——再次证明循环已商品化。
  • Gateway 协议：独立包 packages/gateway-protocol，协议 v4（version.ts:2），TypeBox 帧 schema（frames.ts:40 ConnectParams / :104 HelloOk），req/res/event 三态帧；服务端 upgrade（src/gateway/server-http-upgrades.ts:110），方法注册表（server-methods.ts:43）。会话路由（src/routing/resolve-route.ts:38）按 channel+account+peer 解析到 agentId 绑定——这是"一个网关托管多 agent 人格"的路由核心。
  • 渠道插件体系：抽象 ChannelPlugin（src/channels/plugins/types.plugin.ts:55），生成清单 27 个渠道（bundled-channel-ids.generated.ts:11-148）：WhatsApp/Telegram/Discord/Slack/Signal/iMessage/Matrix/IRC/LINE/MS Teams/Google Chat/飞书/Zalo/Mattermost/Nostr/Twitch/SMS/a2a……CLI 同行只有一个宿主，它有二十七个。
  • Skills：SKILL.md + YAML frontmatter（与 Claude skills 同构，frontmatter.ts:22 解析），五层加载（bundled 50 个→托管→插件→workspace→远程节点），以 XML 目录渐进披露注入系统提示；ClawHub 市场（src/plugins/clawhub.ts）做分发。
  • 权限与信任：exec 两阶段批准（agent 侧 exec-approval-request ↔ gateway 侧 exec-approval-manager + 持久 allowlist）；pairing 配对用 8 位人读码（pairing-store.ts:22-27，TTL 1h/最多 3 待批）+ 设备 ed25519 签名 + /j/ 短码——消费级 agent 的信任建立是"配对"而非"API key"，这是它与开发者 harness 最本质的产品差异；nodes 远程执行走白名单（invoke-system-run-allowlist.ts）+ operator 批准；Docker 沙箱后端可注册（src/agents/sandbox/）。
  • 记忆与人格：MEMORY.md（root-memory-files.ts:7）+ 人格五件套 AGENTS/SOUL/TOOLS/IDENTITY/USER.md（workspace-bootstrap-policy.ts:9-14）——把"system prompt"拆成可读可编辑的人格文件族，是消费级 harness 对上下文工程的独特贡献；会话存 SQLite（worker 线程）；compaction（agent-core/harness/compaction/compaction.ts:322 shouldCompact / :915 compact）。
  • 子代理与 MCP：subagents 工具（subagents-tool.ts:429）+ sessions_spawn；MCP 双向（自身可作 server：src/mcp/channel-server.ts:14；亦可作 client）；hooks 体系（src/plugins/hooks.ts:1015-1302，before_tool_call/inbound_claim/before_prompt_build 等）。

债务：package.json 1275+ 行手工 exports/排除清单；主线程同步 SQLite 存量（仓内 AGENTS.md 自承 legacy）。【未确认】extensions/tencent 的正式渠道注册形态。形态学定位：OpenClaw 证明了 A 范式的循环内核可以服务消费级宿主——它与 opencode 的差异不在"脑"而在"感官与四肢"（渠道=感官，节点=四肢，配对=信任），这正是 4.0 节"第六个收敛信号"的实证。

  1. 第一次更替（2024）：从"自主神话"到"工程现实"。时代①的项目假设模型足够聪明、循环足够简单；时代②的幸存者（OpenHands/cline/browser-use）共同动作是把沙箱、权限闸门、人审交互、可观测性补进内核。死掉的是把循环当产品的（AgentGPT），活下来的是把循环当内核、把工程当产品的。
  2. 第二次更替（2025）：从"框架供给"到"终端分发"。时代③的 44 万星几乎全部来自"npm/brew 一行命令装好"的 CLI harness。框架（B 范式）没有死，但变成了 CLI 的内部依赖——用户要的不是编排原语，是开箱即用的数字员工。
  3. 第三次更替（2026）：从"项目"到"基础设施"。时代④的迁移潮（OpenHands/MetaGPT/goose/opencode 集体换组织）与归档潮（AgentGPT/TaskWeaver/Flowise）说明：agent harness 正在经历数据库、编辑器当年经历过的洗牌——头部收编、腰部出清、协议统一（MCP）。

8.2 趋势预测（逐条标注依据）

⚠ 以下为预测，非代码事实

每条预测先列依据（本报告已证实的事实），再给判断。

预测① CLI harness 的下一战场是"无人值守时长"，而非交互体验（1-2 年）。依据：opencode/codex/gemini-cli 的交互形态已高度趋同（TUI+斜杠命令+MCP），差异只剩沙箱默认姿态与后台任务能力；时代④ OpenHands 平台化、continue 转 read-only 说明纯交互层已无增量。判断：竞争焦点转向后台长任务的存活率——崩溃恢复、上下文压缩质量、跨会话记忆，即 CH.03 图 2 的⑤与记忆卫星。

预测② 协议层继续吞噬框架层：MCP 之后将出现"agent 间协议"的事实标准（1-3 年）。依据：MCP servers 单仓 90k★ 且时代③所有 CLI 均已内置 MCP 客户端；B 范式的多 agent 编排（autogen 停更、crewAI 独存）正在向"单 agent + MCP 工具生态"收缩。判断：A2A（agent-to-agent）类协议将复刻 MCP 的收编路径，多智能体框架的剩余价值沉淀为协议实现与参考编排。

预测③ Rust/Go 重写潮扩散到 B/C 范式，Python 退守编排与算法验证（1-2 年）。依据：codex/goose/openinterpreter 三个 Rust 实现合计 24.9 万星；openinterpreter 从 Python 整体迁 Rust 且 star 未受损。判断：对延迟与分发敏感的 agent 运行时（浏览器控制、桌面自动化、移动端 agent）将优先重写；框架层因生态粘性（LangChain 依赖链）迁移更慢。

预测④ "古典自主循环"将以 RL 训练环境形态复活，而非产品形态（2-3 年）。依据：OpenManus 配套 OpenManus-RL（GRPO agent 强化学习）；AutoGPT 平台化后古典 loop 在代码库中的占比持续萎缩（CH.06 详拆）；SWE-bench 系评测已成为 agent 能力的定价单位。判断：目标驱动的长程自主循环的主战场转向训练侧（环境即数据集），产品侧则收敛为"人在回路的长任务监督台"。

预测⑤ 榜单将再洗牌：平台对照组（n8n/dify 类）与 agent 榜合流（2-3 年）。依据：ChatDev 2.0 已转零代码编排平台；AutoGPT 平台化；suna/sim 全家桶化；dify/n8n 均已内建 MCP 与 agent 节点。判断："工作流平台 + agent 节点"与"agent harness + 可视化编排"双向奔赴，2027 年的榜单将难以区分两类项目——分水岭不再是形态，而是循环驱动权在谁手里（人编排的图，还是模型自驱的环）。

9.3 总结论：harness 物种的 2026 形态学

  1. 循环已商品化，工程分层定胜负。14 仓的 agent loop 结构差异已小到可以互相转写（codex fork 直接继承）；竞争发生在权限闸门（codex 三层 vs goose 裸 spawn）、上下文治理（压缩工艺谱系）、动作表达（tool_use/补丁方言/代码即动作/DOM 索引）、编排边界（子代理隔离模型）四个非循环层。
  2. harness 正沿 RPC 边界解体为"内核+多宿主"。codex app-server、goose ACP、cline hub、OpenHands agent-server 四家独立收敛到同一形态——这与 LSP 当年把编辑器与语言服务解耦是同构事件；预测harness 的"LSP 时刻"将在 1-2 年内以某家协议（ACP 或 MCP 扩展）事实标准化收场。
  3. 2026 是收编年：open-interpreter 变成 codex fork、OpenHands 前后端分家、四个头部项目迁移组织、三个经典归档——物种数量在减少，单物种体量在膨胀，协议层（MCP）收一切工具税。
  4. 消费级入口超越开发者入口：OpenClaw 391k★ vs 开发者 CLI 榜首 210k★——"个人 agent harness（消息渠道+自有设备）"已被验证为比"编程 agent"更大的流量形态，而它的内核与本报告所有 A 范式项目是同一物种（详见 4.1）。
  5. 对自建 harness（如 DSH 类工程）的可移植清单：循环照抄 codex turn 语义即可；真正要自研的是——权限规则引擎（参考 gemini-cli 分层 TOML）、压缩触发器（参考 cline 双策略）、子代理隔离边界测试（参考 goose 委派树固化用例）、以及 AGENTS.md 工程纪律——并警惕本报告 7.7 节所有巨型文件的下场。
