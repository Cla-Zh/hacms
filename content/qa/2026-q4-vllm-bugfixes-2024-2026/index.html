💡 关键洞察

1. 「推理引擎」复杂度 = 「并行策略 × 量化格式 × 注意力后端」笛卡尔积, Bug 几乎都踩在这三个轴上

CUDA 内核 107 + TP 95 + PP 22 + DP 19 + EP 8 + 各种 Quantization 共 200+ 个 PR, 占了总量的近 1/4。最常见的失败模式是: 新硬件 (Blackwell SM100/SM103/SM121) 上的回归 (PR #38730 GB300 hang, #35568 SM121 Marlin 排除, #38730 TRTLLM SM100 限制) + 新内核 dtype 不匹配 (Marlin FP8 + MLA activation, FP4 + EP 精度) + 跨 rank 同步 (MessageQueue 绑定 master_addr, DeepEP LL cooperative launch hang)。

2. 新模型适配期是 Bug 高发期 (Qwen 系列尤为突出)

Qwen 3.5 / Qwen3-Next / Step3 这类带 GatedDeltaNet 线性注意力 + MoE 结构的混合模型, 由于结构新, 几乎每个子系统都要打补丁: PP 下 residual KeyError (PR #37622)、LoRA fused in_qkvz_proj (PR #37912)、GDN chunked prefill dtype (PR #37338)、MarLIN in_proj_ba at TP≥2 (PR #36329)、MLA Marlin FP8 prefill (PR #38771)。

3. KV Cache 是「快慢变量交叠」

KV Cache 内部 (41 个 PR) 涉及多维问题: 空间维度 (workspace resize 漏内存 PR #39226, dummy run NaN 写入 null block PR #39444, --max-model-len=-1 导致请求 hang PR #39102) + 数值精度 (MLA kv_b_proj dtype PR #38771, KV scale 加载 PR #39418, compressed-tensors scale PR #35430) + 运行时一致性 (V1 dummy run 写入 0 而非 NaN)。外部 KV Connector (Mooncake / UCM / MORI / LMCache) 7 个 PR 多在测试修补, 真正大修还是在 Connector 自身代码。

4. 工具调用 + Reasoning Parser 是「协议层」长期脆弱点

44 个 PR 中大量是「streaming token 泄漏」、「reasoning block 未闭合」、「type 解析 $ref/anyOf/oneOf」类问题 (PR #38579 Kimi-K2 token 泄漏, PR #38973 Qwen3Coder type resolution, PR #35687 <tool_call> 隐式 reasoning 结束)。这类问题只能等模型真实部署 + 多轮对话才能暴露, 单元测试覆盖不到。

5. UTF-8 / 多字节字符引发「无声 Bug」

PR #38732 (bench_serve 在 HTTP chunk 边界切到 UTF-8 多字节字符时崩溃)、PR #34875 (V1 logprobs 中 byte-fallback token 3 字节 UTF-8 序列显示为空串) — 这类 bug 在生产环境潜伏很久, 只在中文字符、emoji、特殊引号密集场景下才出现。
